PART 02

三个任务

HUB 组网 → 配置主机 → 测试连通性。

Task 01

任务一 · HUB 组网

定义

共享式局域网

所有主机共享同一条传输总线,任何时候只允许一台主机占用总线。

核心

集线器(HUB)

以集线器为核心组建的局域网共享传输总线。

冲突域

同一冲突域

所有连在 HUB 上的主机处于同一个冲突域。

带宽

带宽共享

n 台主机共享 10/100 Mbps,每台实际可用约 1/n。

HUB Topology

HUB 星型连接 · 共享总线

[ Alice-PC ] | [ Bob-PC ] | [ Chris-PC ]-----------[ HUB ]-----------[ Dave-PC ] | [ Eve-PC ] | [ Frank-PC ]

表面上是星型(每台 PC 独立连线),但 HUB 内部把所有端口连到同一条总线——本质仍是共享介质。

PART 03

拓扑结构

网络的「骨架」——5 种基本形态。

Topology

网络拓扑结构 · 概念

抽象

点与线

把工作站、服务器等网络单元抽象为「点」,把网络中的电缆等通信介质抽象为「线」。

意义

几何图形

用点和线的几何图形抽象出网络系统的具体结构。

常见

五种基本结构

总线型、星型、环形、树型、网状型——五种基本拓扑。

选择

按需选择

拓扑决定布线方式、扩展难度和故障影响范围。

Bus

总线型拓扑 · 一根主干

===[ Terminator ]====PC1====PC2====PC3====[ Terminator ]=== 50Ω | | | 50Ω [ HUB ] [ HUB ] [ HUB ]

所有节点共用一根主干电缆;两端终端电阻防止信号反射。

Bus · Pros & Cons

总线型 · 优缺点

优点

简单、广泛

结构简单、易于扩充;曾是 10BASE-2 / 10BASE-5 的主流形态。

缺点

故障严重

总线任一处故障将导致整个网络瘫痪;故障诊断困难。

缺点

带宽共享

总线任务重,易产生瓶颈;传输速率有限。

场景

已淘汰

现代 LAN 几乎不用——但概念仍重要,影响后世拓扑理解。

Star

星型拓扑 · 现代 LAN 的骨架

[ Alice-PC ] | [ Bob-PC ] | [ Chris-PC ]-----------[ HUB/SW ]-----------[ Dave-PC ] | [ Eve-PC ] | [ Frank-PC ]

所有节点通过独立链路连到中央节点——早期是 HUB,现代是交换机。

Star · Pros & Cons

星型 · 优缺点

优点

易建易管

结构简单、易于建网;单点故障只影响一台主机。

缺点

布线与中央

布线费用大;对中央节点要求高。

应用

现代主流

以太网绝大多数采用星型拓扑——办公 / 校园网的事实标准。

变体

树型升级

多个星型级联 → 树型——核心/汇聚/接入三层架构。

Ring

环形拓扑 · 单向令牌环

PC1
PC2
PC3
PC4

数据沿环单向传输;令牌在环上传递,获得令牌的节点才能发送——典型应用:令牌环 / FDDI。

Ring · Pros & Cons

环形 · 优缺点

结构

闭合环路

所有节点通过点到点链路组成闭合环路;数据单向传输。

优点

路径确定

路径选择简单(只有一个方向);公平。

缺点

故障即崩

单点故障会引起整个网络崩溃(双环可缓解)。

应用

令牌环、FDDI

IBM Token Ring(4/16 Mbps)、FDDI(100 Mbps 光纤)。

Tree

树型拓扑 · 星型的层次化

[ Core Switch ] | __________|__________ / | [ Switch ] [ Switch ] [ Switch ] / \ / \ / [PC1][PC2][PC3][PC4][PC5][PC6][PC7][PC8]

树型 = 多个星型按层次级联——核心层、汇聚层、接入层。

Tree · Pros & Cons

树型 · 优缺点

结构

星型延伸

树型拓扑实际上是星型的延伸。

优点

层次清晰

层次结构清晰,便于按部门 / 楼层划分网络;扩展性好。

应用

校园网

校园网通常是树型 + 星型的组合。

缺点

根节点依赖

根节点 / 核心节点故障 → 大量节点失联。

Mesh

网状型拓扑 · 多路径冗余

结构

多路径

每个节点至少两条到其他节点的路径——完全或部分网状。

优点

高可靠

任意一条链路故障,流量自动绕行其他路径。

缺点

复杂昂贵

布线多、配置复杂、成本高。

应用

Internet 骨干

Internet 骨干采用部分网状,保证「任何两点都可达」。

Hybrid

混合型拓扑 · 真实工程

  • 实际工程中很少只使用单一拓扑
  • 典型组合:树型 + 星型(校园网)、网状 + 星型(运营商骨干)
  • 选用原则:「综合考虑性能、成本、可靠性」
  • 现代 LAN 几乎都是星型 + 树型的混合
  • 核心交换机双归属、双电源、链路聚合 → 局部网状

Compare

5 种拓扑 · 一表对比

拓扑结构优点缺点典型应用
总线型一根主干简单一处故障全瘫10BASE-2(已淘汰)
星型以中央为中心易建易管中央节点关键以太网主流
环形闭合环路路径确定单点故障令牌环、FDDI

PART 04

介质访问控制 · MAC

共享介质上,谁可以说话?——三种经典方法。

Why MAC

为什么需要介质访问控制?

原因

共享介质

共享式局域网的传输介质是共享的。

规则

半双工

数据传输按「半双工」——任一时刻只有一个方向。

风险

冲突

两个或多个节点同时发送将产生「冲突」。

方案

MAC 协议

需要介质访问控制(MAC)协议协调各节点。

解决

顺序问题

解决「谁先发」「冲突怎么办」。

效果

共享而不乱

共享介质依然有序——「多而不乱」。

MAC Methods

三种经典介质访问控制

CSMA/CD

以太网

载波侦听多路访问 / 冲突检测——先听后发、边听边发、冲突停发、延迟重发。

Token Ring

令牌环

通过令牌控制发送权,令牌在环上依次传递。

Token Bus

令牌总线

总线上的节点组成逻辑环,按令牌传递顺序获得发送权。

CSMA/CD

CSMA/CD · 十六字口诀

01
先听后发
发送前先侦听信道是否空闲
02
边听边发
发送过程中继续侦听
03
冲突停止
检测到冲突立即停止
04
延迟重发
退避算法后重新尝试

CSMA/CD 是以太网的核心机制——先听再说、听不清就停,体现了「共享而不乱」的智慧。

Token Ring

令牌环 · 工作原理

  • 空闲时:令牌沿环绕行;任何站点必须先获得令牌才能发送
  • 发送站点:捕获令牌 → 发送数据帧 → 释放令牌 → 等待数据绕环一周被吸收
  • 中间站点(目的地址非己):转发环上的数据帧
  • 接收站点(目的地址为己):拷贝数据帧,然后继续转发
  • 令牌机制保证任一时刻只有一台站点在发送,从根本上避免冲突
  • 效率高但单点故障严重——已被淘汰,只作历史知识

FDDI

FDDI · 双环自愈

目的

可靠性

解决令牌环的可靠性问题——单环断裂全瘫。

形态

逆向双环

主环 + 副环,逆向旋转。

正常

只用主环

正常只使用主环传送数据,副环处于备份状态。

故障

环回自愈

主环失效时,故障点两侧的节点环回成单环继续通信。

PART 05

以太网标准与组网

10/100/1000 Mbps 的演进——同一根双绞线,越来越快。

Ethernet Standards

以太网主要技术标准

标准速率介质拓扑年代
10BASE-510 Mbps粗同轴电缆总线型1980s
10BASE-210 Mbps细同轴电缆总线型1980s
10BASE-T10 MbpsUTP 双绞线星型1990
100BASE-TX100 Mbps5 类 UTP星型1995
1000BASE-T1 Gbps超 5/6 类 UTP星型1999
10GBASE-T10 Gbps6A/7 类 UTP星型2006

BASE 表示基带传输;后面的数字 / 字母表示介质与最大段长(如 5 = 500 m,T = Twisted Pair)。

10 vs 100

10 Mb/s 与 100 Mb/s · 单 HUB 组网

10 Mb/s

早期配置

10 Mb/s 网卡 + 3 类以上 UTP + 10BASE-T HUB;每段 UTP ≤ 100m。

100 Mb/s

主流配置

100 Mb/s 网卡 + 5 类以上 UTP + 100BASE-TX HUB;每段 UTP ≤ 100m。

设备

其他配件

RJ-45 水晶头、网线、HUB 指示灯——指示灯亮表示链路正常。

局限

共享总线

所有端口共享同一冲突域——性能受限。

Multi-HUB

多 HUB 级联 · 扩大规模

  • 适用环境:计算机数量超过单个 HUB 端口数;位置分散
  • 级联方式 A:HUB 的级联端口与另一 HUB 的普通端口(直通线)
  • 级联方式 B:两台 HUB 的普通端口互连(交叉线)
  • 注意:10 Mb/s HUB 与 100 Mb/s HUB 不能相互级联
  • 级联后整个网络仍是一个冲突域
  • 级联会增加网络延迟——不宜超过 4 级

Cascade

多 HUB 级联结构 · 两种形态

平行式

级联

若干 HUB 通过级联端口串接,所有节点处于同一层次。

树形式

级联

主 HUB 接多个子 HUB,形成层次结构;扩展端口更多。

5-4-3 规则

10 Mb/s 限制

任意两个节点之间最多 5 个网段、4 个 HUB;最大 500m;无环路。

100 Mb/s 限制

更严格

任意两个节点最多经过 2 个 HUB;最大覆盖 205m;无环路。

5-4-3 Rule

10 Mb/s 以太网 · 5-4-3 规则

[PC]---[HUB]---[HUB]---[HUB]---[HUB]---[PC] | 1 2 3 4 segment1 seg2 seg3 seg4 seg5 | max 5 segments · 4 HUBs · 3 populated

5 段、4 个 HUB、3 个有设备的段 ——这是 10BASE-T 网络的理论上限。

PART 06

共享式 vs 交换式

从 HUB 到 Switch——LAN 的革命性升级。

Shared vs Switched

共享式 vs 交换式 · 一表对比

维度共享式(HUB)交换式(Switch)
工作方式所有端口共享总线每端口独立冲突域
冲突大量冲突无冲突
带宽共享(总带宽/n)每端口独占
全双工否是
MAC 学习无有 MAC 表
现代地位已淘汰主流

Compare · Detail

共享式 vs 交换式 · 详细对比

旧 · 共享式

HUB 时代

所有 PC 共用同一条总线——A 发包时 B/C/D 都被迫收到。

冲突严重、带宽均分、需要 MAC 地址过滤。

新 · 交换式

Switch 时代

每端口是独立的微冲突域——A 与 B 通信不影响 C 与 D。

全双工、并行通信、每端口独享带宽。

Case 01

案例 1 · 共享式 LAN 越用越慢

故障现象

SIK 工作室从 3 人扩到 12 人,都接到同一个 100M HUB。后来发现:每到下午 3 点,所有人访问共享文件都很慢。

诊断

HUB 是共享 100M,12 台 PC 平分:每台 ≈ 8.3 Mbps——再加上冲突、退避重传,实际可用更少。

解决

把 HUB 换成交换机——每端口独立 100M,12 台 PC 同时通信互不影响。

结论

✅ HUB 的「共享总线」是性能瓶颈;Switch 的「独享带宽」才能撑住多用户。

Case 02

案例 2 · HUB 级联过多

故障现象

某部门为扩大覆盖,把 5 个 HUB 串接(每 HUB 100M 共享)。ping 延迟从 1ms 涨到 100ms+。

问题诊断

5-4-3 规则限制:10 Mb/s 最多 4 个 HUB / 5 段;100BASE-TX 更严格——最多 2 个 HUB。

每 HUB 增加延迟 + 增加冲突概率。

解决

用交换机替代多 HUB 级联——交换机每个端口独立,不增加冲突域。

结论

⚠️ HUB 级联不是万能的——现代 LAN 应「Switch 到底」。

Switch vs Hub

Switch vs Hub · 工作方式

Hub

广播所有

A 发包 → HUB 把帧复制到所有其他端口——B/C/D 都要看一下,只有目的才收。

Switch

精准转发

A 发包 → Switch 查 MAC 表,只把帧转发到B 所在的端口——C/D 完全不知道。

关键差异:HUB = 广播(带宽浪费);Switch = 定向(带宽高效)。

MAC Table

Switch 的 MAC 地址学习

  • 每台 Switch 内部维护一张MAC 地址表
  • 每收到一帧,记录 源 MAC + 端口号 → 学习
  • 转发时,查目的 MAC:找到 → 单播;找不到 → 广播
  • 一段时间不用的 MAC 条目会被老化(默认 5 分钟)
  • 所以 Switch 启动后要「学习一段时间」才能正常工作

Learning

Switch 的学习过程 · 4 步

  1. A 给 B 发帧 → Switch 从 Port 1 收到帧,记录:MAC_A → Port 1
  2. 查 MAC 表,目的 MAC_B 不存在 → 广播到所有其他端口
  3. B 收到并回复 → Switch 从 Port 2 收到,记录:MAC_B → Port 2
  4. 以后 A↔B 的通信直接 Port 1 ↔ Port 2,不再广播

这就是 Switch 的「自学习」能力——无需人工配置,插上就用。

Switch · Pros

交换机的 4 大优势

独享带宽

每端口 100M/1G

每端口独立带宽——12 人同时跑满,理论总带宽 12×100M = 1.2 Gbps。

无冲突

微冲突域

每端口是独立的冲突域——CSMA/CD 几乎失效,可以全双工。

自学习

MAC 表

自动学习 MAC,精准转发——无需人工配置。

扩展性

任意级联

多台 Switch 级联不影响性能——突破 5-4-3 限制。

Full Duplex

全双工 · 收发同时进行

  • HUB 时代:半双工——同一时刻只能发或收
  • Switch 时代:全双工——发送和接收同时进行
  • 理论带宽 = 2 × 端口速率:100M 全双工 = 收 100M + 发 100M = 200M
  • 无需 CSMA/CD——因为不会冲突
  • 现代网卡默认自协商到全双工

Broadcast Domain

广播域 vs 冲突域

冲突域

Collision Domain

可能发生冲突的范围。HUB 所有端口同一冲突域;Switch 每端口独立冲突域。

广播域

Broadcast Domain

广播帧能到达的范围。默认所有 Switch 端口同一广播域;路由器/ VLAN 可分割。

关键

HUB 分冲突不分广播

HUB 既不分割冲突域、也不分割广播域——所以性能差。

关键

Switch 分冲突不分割广播

Switch 分割冲突域但不分割广播域——广播太多会拖累所有主机(广播风暴)。

Broadcast Storm

广播风暴 · 共享介质的隐忧

  • 广播:发给「所有主机」的包——如 ARP、DHCP、某些协议
  • 广播域越大,广播占用带宽越多
  • 广播风暴:网络成环、广播循环转发 → 占满所有带宽
  • 防御:路由器分割广播域 / VLAN 划分广播域 / 生成树协议
  • → 下一章我们会讲 VLAN 与路由器,真正实现「分割」

Case 03

案例 3 · 真实工程:HUB 换 Switch

背景

某公司 30 人办公网,原为 1 台 24 口 HUB。员工反映网络卡顿、视频会议丢帧。

诊断

用 Wireshark 抓包:60% 的流量是ARP 广播;P2P 文件传输占满总线。

HUB 是全网段广播——任何一台机的广播包全网都收到。

解决

把 HUB 替换为 2 台 24 口交换机,用级联线连接。

结果:卡顿消失,视频流畅,办公效率提升。

结论

✅ Switch 的「独享带宽 + MAC 学习」是 HUB 的全面升级。

Why Switch

为什么现代 LAN 全部用 Switch?

HUB 已淘汰

为什么不用 HUB

共享带宽、广播泛滥、冲突严重;无法支持现代应用(视频、云)。

Switch 主流

Switch 优势

独享带宽、MAC 学习、全双工;支撑千兆 / 万兆现代网络。

成本

价格差不多

现在交换机价格已与 HUB 相当——没有理由再用 HUB。

演变

100M → 1G → 10G

端口速率持续升级,价格持续下降。

核心层 → 汇聚层 → 接入层——大型 LAN / 校园网的标准架构。

Misconceptions

常见误解 · 别踩坑

  • 「HUB 和 Switch 都能用」——错。HUB 早已淘汰,Switch 价格更低性能更好。
  • 「100M Switch 每端口 100M」——错。100M Switch 是「每端口独享 100M」,不是 100M/n。
  • 「Switch 隔离广播」——错。Switch 隔离冲突但不隔离广播——广播域默认全网。
  • 「MAC 地址全球唯一」——理论上,但虚拟机、克隆会重复。
  • 「CSMA/CD 已过时」——部分对。Switch 全双工下基本不用,但 HUB 仍要。

Pitfalls

工程师常犯的 5 个错

  • 用 HUB 组大网　——人多了就卡
  • 忘了关闭 STP　——冗余链路直接广播风暴
  • 配置错全双工　——一端全双工、另一端半双工 → 性能极差
  • Switch 当 Hub 买　——便宜 Switch 可能没 MAC 学习功能
  • 广播域过大　——不划分 VLAN,几百台机器互发广播
