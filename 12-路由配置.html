PART 02

路由原理

路由器怎么「决定」把包发给谁?

Router

路由器 · 三层设备

工作层次

网络层

看 IP 地址 选路——基于目的 IP 查路由表。

接口

多接口

每个接口属于不同子网,路由器连接多个网络。

路由表

选路依据

维护一张 目的网络 → 下一跳 的映射表。

核心

逐跳转发

每个路由器只看下一跳——不关心整条路径。

Routing Table

路由表 · 路由器的「地图」

Router# show ip route
Codes: C - connected, S - static, R - RIP, O - OSPF, B - BGP, * - candidate default Gateway of last resort is 192.168.1.2 to network 0.0.0.0 C 192.168.1.0/24 is directly connected, FastEthernet0/0 C 192.168.2.0/24 is directly connected, FastEthernet0/1 S* 0.0.0.0/0 [1/0] via 192.168.1.2

C = 直连;S = 静态;S* = 默认;R/O = 动态协议。

Lookup

查表过程 · 最长前缀匹配(计算)

计算 · 最长前缀匹配(目的 IP 192.168.20.5)
01
提取目的 192.168.20.5 → 二进制 11000000.10101000.00010100.00000101
02
匹配条目 1 192.168.0.0/16 = 11000000.10101000 前 16 位匹配 ✓ 16 位前缀
03
匹配条目 2 192.168.20.0/24 = 11000000.10101000.00010100 前 24 位匹配 ✓ 24 位前缀 — 更精确
04
匹配条目 3 0.0.0.0/0 0 位匹配 ✓ 0 位前缀 — 兜底

Lookup

查表过程 · 最长前缀匹配(步骤)

计算 · 选出最优条目并转发
01
选择结果 比较前缀长度:24 > 16 > 0 → 选 192.168.20.0/24 路由 最长前缀匹配
02
转发 包发给下一跳 10.0.0.2 R2 继续查表 递归选路
  1. 收到 IP 包,提取目的 IP(如 192.168.20.5)
  2. 逐条匹配路由表条目
  3. 选择前缀最长的条目(如 192.168.20.0/24 的 24 位 > 0.0.0.0/0 的 0 位)
  4. 把包发给该条目的下一跳
  5. 没有匹配?→ 发给默认路由(0.0.0.0/0)

Methods

三种路由方式 · 对比

方式配置优点缺点
直连路由自动无需配置只能到达直连网段
静态路由手动可控、安全大型网络工作量大
动态路由自动学习自适应、易扩展需要运行协议(RIP/OSPF)

本章用静态路由;后续章节介绍动态路由(RIP / OSPF)。

Static

静态路由 · 5 个特点

  • 手工配置:管理员一条一条写
  • 单向:每条路由只描述一个方向(回程要单独配)
  • 不自动适应:链路故障时路由不会自动切换
  • 适合小网络:稳定、可控、易理解
  • 默认路由:0.0.0.0/0 兜底——出口路由器必配

Default

默认路由 · 0.0.0.0/0

定义

兜底路由

路由表中最不具体的条目——任何未匹配的目的都走它。

场景

Stub 网络

只有一个出口的网络——配默认路由指向出口。

命令

ip route 0.0.0.0 0.0.0.0 <next-hop>

目标:0.0.0.0/0 → 下一跳:出口路由器 IP。

优先级

最低

默认路由的前缀最短（0 位）——按最长前缀匹配，最后才被选。

Default Route

默认路由 · Stub 网络

当路由器只有一个出口时——配默认路由简化管理:

R1>
R1> enable R1# configure terminal R1(config)# no ip route 192.168.20.0 255.255.255.0 10.0.0.2 R1(config)# ip route 0.0.0.0 0.0.0.0 10.0.0.2 ! 等价于:R1 把所有非本地流量都发给 R2

默认路由适合只有一个出口的场景——大型网络应配精确静态路由。

Troubleshoot

故障排查 · 3 大方法

  1. show ip interface brief　查看接口状态(IP/UP/DOWN)
  2. show ip route　查看路由表是否完整
  3. traceroute　端到端定位断在哪一跳

Pitfalls

静态路由的 4 个坑

坑 1

单向配置

A → B 配了路由,B → A 没配——单向通。

坑 2

下一跳不可达

下一跳 IP写错,路由表有项但转发不了。

坑 3

掩码错误

掩码输错导致路由不精确,长前缀被覆盖。

坑 4

出口 NAT 缺失

外网能 ping,外网 ping 不进来——需配 NAT。

Case 01

案例 · 单向配置

故障现象

PC1 ping PC3 通,但 PC3 ping PC1 超时。

诊断

R1 配了 ip route 192.168.20.0 ... 10.0.0.2(去程),但R2 漏配回程路由:

ip route 192.168.10.0 ... 10.0.0.1

解决

在 R2 上补上回程路由。

结论

⚠️ 静态路由一定要配对——双向都要有。

Case 02

案例 · 下一跳 IP 错误

故障现象

R1 配了静态路由但 PC1 ping PC3 仍然超时。

诊断

查 R1 路由表:ip route 192.168.20.0 ... 10.0.0.99 → 下一跳 IP 错误(应该是 10.0.0.2)。

解决

删除错误路由,重新配置:

no ip route 192.168.20.0 255.255.255.0 10.0.0.99

ip route 192.168.20.0 255.255.255.0 10.0.0.2

结论

✅ show ip route + 检查下一跳 IP 是排查基本功。

Case 03

案例 · 路由表有项却不通

故障现象

R1 路由表显示有 192.168.20.0/24 via 10.0.0.2,但 PC1 ping PC3 仍超时。

诊断

用 show ip interface brief 发现本端接口 UP，但对端 R2 的 Fa0/1 实际不通（线缆接错端口 / 对端接口 DOWN）——路由表条目还在，下一跳实际不可达。

解决

检查网线两端接口 → 对端 no shutdown;核对两端接口 UP。

结论

⚠️ 路由表有项 ≠ 路由能通——还要看链路两端的实际状态（本端 UP、对端 DOWN 同样不通）。

Misconceptions

常见误解 · 别踩坑

  • 「配置路由后必通」——错。还要接口 UP + 下一跳可达 + NAT。
  • 「路由表项越多越好」——错。路由多 = 转发表大 = 查表慢。
  • 「默认路由 = 静态路由」——部分错。默认路由是静态路由的特例(0.0.0.0/0)。
  • 「路由表会自己更新」——部分错。静态路由不会,只有动态路由协议才会。
  • 「路由器只做选路」——错。现代路由器还做 NAT、ACL、QoS、防火墙等。

Compare

静态 vs 动态 · 何时选谁?

静态路由

小网络

< 10 个子网

需要完全控制

→ 学校、小公司

动态路由

大网络

> 10 个子网

需要自适应和冗余

→ 运营商、大企业

Redistribute

路由重分发 · 多协议互通

  • 重分发(Redistribution)——不同路由协议之间交换路由信息
  • 如:OSPF 学到的路由导入到 RIP 中;反之亦然
  • 命令:redistribute ospf 1 metric 5(在 RIP 进程下;必须带 metric,否则路由不会注入)
  • 需要指定度量值(metric)——不同协议度量单位不同
  • 注意:重分发可能造成路由环路或次优路由
  • 工程上:尽量统一一种动态路由协议,避免重分发

Route Maps

路由策略 · Route Map

作用

灵活选路

不仅能选路,还能控制哪些路由可被通告。

典型用法

过滤路由

拒绝某些网段的路由——「禁止从 R2 访问财务部」。

修改度量

修改 metric

为不同流量调整路径优先级。

标签

路由标记

为路由添加 tag,与 BGP 路由策略联动。

PBR

策略路由 · PBR

作用

超越目标

不只根据目的 IP,还可根据源 / 协议 / 端口选路。

典型场景

电信走电信

让访问电信的流量走电信 ISP,联通走联通 ISP。

命令

route-map

用 route-map 定义策略 + ip policy route-map 应用到接口。

IPv6

IPv6 与路由 · 过渡

  • IPv4 路由表 → IPv6 路由表(类似机制)
  • IPv6 RIPng = RIP 在 IPv6 上的版本
  • OSPFv3 = OSPF 在 IPv6 上的版本(独立协议号 89)
  • IPv6 地址 128 位,写法:2001:da8:1234::1
  • 静态路由命令略不同:ipv6 route 2001:db8::/32 ...
  • 双栈:设备同时跑 IPv4 和 IPv6 路由

Network Design

网络设计原则 · 5 条

  • 层次化　核心层 / 汇聚层 / 接入层
  • 冗余性　链路双归属、设备双机
  • 可扩展　模块化设计,新部门易接入
  • 简洁性　能用静态就不上动态
  • 可管理　集中监控、日志告警

Case 04

案例 · 路由环路

故障现象

两台路由器配错静态路由互相指向对方——网络不通,traceroute 显示包在两台路由器间循环。

诊断

R1 的路由指向 R2;R2 的路由指向 R1——形成路由环路。

解决

删除错误路由,改为 R1 → R3、R2 → R3(都指向中间路由器)。

结论

✅ 静态路由必须避免双向互指——形成环路必死。

Case 05

案例 · 汇总路由黑洞

故障现象

配 192.168.0.0/16 汇总后,部分网段不可达——但其他正常。

诊断

192.168.0.0/16 涵盖 192.168.0.0–192.168.255.255,但实际某些段走另一个出口。汇总路由把流量送到没有明细路由的路由器 → 黑洞。

解决

为走其他出口的网段添加明细静态路由(比汇总更精确)。

结论

⚠️ 汇总路由 + 明细路由 可以共存——汇总管大多数,明细管特殊。

PART 03

扩展 · NAT 网络地址转换

IPv4 地址耗尽的"工程妥协"——多私网共享 1 公网 IP。

Why NAT

为什么需要 NAT？

问题

IPv4 枯竭

32 位 = 43 亿地址，全球 80 亿人不够分。

现实

私有 IP 大量部署

10/8 + 172.16/12 + 192.168/16 三大段，但不能路由公网。

解决：NAT（Network Address Translation）—— 边界路由器把私网 IP 翻译为公网 IP。

3 Types

NAT 三大分类

静态

静态 NAT

1 私网 IP ↔ 1 公网 IP
适用：服务器对外发布（如公司官网）

动态

动态 NAT

1 私网 IP 占用公网 IP 池中的 1 个
适用：简单访问外网

PAT ★

PAT（端口复用）

多私网 IP 共享 1 公网 IP（按端口区分）
适用：家庭 / 办公网最常用

How PAT

PAT 工作原理（端口复用）

也叫 NAT overload——通过端口号区分不同内网主机。

192.168.1.100:5001  → 203.0.113.1:8001  (访问 baidu)
192.168.1.101:5001  → 203.0.113.1:8002  (访问 baidu)
192.168.1.102:5001  → 203.0.113.1:8003  (访问 baidu)

路由器维护一张 NAT 转换表（私网 IP:Port ↔ 公网 IP:Port）。
16 位端口 → 理论上 1 公网 IP 可共享 6 万+ 内网 IP。

PAT Config

PAT 配置 · 4 步流程

1

interface fa0/0  →  ip nat inside

标记内网口

2

interface fa0/1  →  ip nat outside

标记外网口

3

access-list 1 permit 192.168.0.0 0.0.255.255

定义哪些内网要 NAT

4

ip nat inside source list 1 interface fa0/1 overload

启用 PAT（overload = 端口复用关键字）

验证：show ip nat translations 查看转换表 / show ip nat statistics 看统计。

Limits

NAT 的局限

影响 1

P2P / VoIP

P2P 软件需主动连入，NAT 阻挡。VoIP / 视频会议类似。

影响 2

主动入站连接

外部主动连入需要端口映射（static NAT）。

影响 3

追溯困难

转换后原始 IP 丢失，难以追溯到具体内网用户（需 NAT 日志）。

解决

NAT 穿透 / IPv6

STUN / TURN / ICE 协议 / 端到端 IPv6 直连。
