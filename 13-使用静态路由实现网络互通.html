Clock

串行链路 · 时钟频率

  • DCE 端(路由器 DCE 接口)需配置 clock rate 64000
  • DTE 端不需要配时钟
  • Packet Tracer 中连接串口时选择 Serial DCE 线缆，先点击的一端为 DCE 端
  • 物理串口需用 V.35 串口线
  • 串口默认速率 1.544 Mbps(T1)

Routes

路由表分析 · 3 跳

  • R1 需要知道:到 192.168.20.0/24 走 R2;到 192.168.30.0/24 走 R2
  • R2 需要知道:到 192.168.10.0/24 走 R1;到 192.168.30.0/24 走 R3
  • R3 需要知道:到 192.168.10.0/24 走 R2;到 192.168.20.0/24 走 R2
  • 每台路由器都要知道 2 个非直连网段
  • 也可以用默认路由简化:Stub 路由器只需 1 条 0.0.0.0/0

Summary

汇总路由 · 配置与验证

计算 · 汇总结果与命令
01
汇总结果 前 16 位统一:11000000 10101000 前缀 16 位,掩码 255.255.0.0 后 16 位任意
02
命令 ip route 192.168.0.0 255.255.0.0 20.0.0.1 所有 192.168.x.x 走 R2 替代 2 条明细

当一个路由器下挂多个子网时——可用汇总路由减少条目:

R3(config)#
R3(config)# ip route 192.168.0.0 255.255.0.0 20.0.0.1

一条 192.168.0.0/16 汇总北京 / 上海两个 LAN 网段——替代 2 条具体路由（广州 LAN 是直连，不受影响）。

⚠️ 仅当 所有 192.168.x.x 都从 R2 走时才安全;否则会形成错误路由。

Case 01

案例 · 时钟未配

故障现象

串行链路 R1 ↔ R2 show ip interface brief 显示 Serial0/0/0 down down。

诊断

DCE 端没有配 clock rate——串口无法同步时钟,链路不起。

解决

在 DCE 端接口配置:clock rate 64000

结论

✅ 串口链路两端必须各 no shutdown,且 DCE 端配时钟。

Case 02

案例 · 路由汇总陷阱

故障现象

R3 上配了 192.168.0.0/16 via 20.0.0.1 后,北京 192.168.10.10 突然 ping 不通。

诊断

汇总路由太笼统——北京属于 192.168.10.0,但汇总后从 R2 转发,而 R2 缺少 192.168.10.0 的明细路由(本实验可先在 R2 上删除该条明细路由再复现) → 路由黑洞。

解决

改回明细路由:ip route 192.168.10.0 255.255.255.0 20.0.0.1(经 R2 的 S0/0/1)

结论

⚠️ 汇总路由必须保证路径一致;否则会形成路由黑洞。

Recap

本章小结

  1. 多跳网络:每台路由器只看下一跳
  2. 3 路由器拓扑:每台需知非直连网段的路由
  3. 串行链路:DCE 端配 clock rate
  4. 下一跳 vs 出接口:点对点用出接口,多路访问用下一跳,拿不准两个都写
  5. 浮动静态路由:AD 调高做备份,主路径失效时自动浮上来接管
  6. 默认路由:Stub 网络的简化方案
  7. 汇总路由:减少路由表条目,但要谨慎
