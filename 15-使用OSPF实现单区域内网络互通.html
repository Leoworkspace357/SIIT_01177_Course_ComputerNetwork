PART 02

OSPF 原理

链路状态算法——每台路由器都画一张「全网地图」。

LSA

OSPF 的 3 步工作过程

STEP 01
发现邻居
Hello 包建立邻居关系
STEP 02
泛洪 LSA
每台路由器向全网通告自己的链路
STEP 03
计算路由
每台路由器用 Dijkstra 算法算出最短路径

三步完成后——每台路由器都有完整的「链路状态数据库」,算出的路由不会环路。

LSDB

链路状态数据库 · LSDB

  • 每台路由器都维护相同的 LSDB(链路状态数据库)
  • LSDB 包含网络中所有路由器的链路状态信息
  • LSA(Link-State Advertisement)是 LSDB 的基本单位
  • LSA 通过可靠泛洪传播到整个区域
  • 同一区域内的路由器 LSDB 完全一致
  • 基于 LSDB,每台路由器独立计算路由(SPF)

Dijkstra

Dijkstra 算法 · 最短路径

  • 以本路由器为根,建立一棵最短路径树
  • 每个节点(路由器 / 网络)有开销(cost)
  • OSPF 默认 cost = 100 Mbps / 链路带宽
  • 10M 链路 cost = 10;100M = 1;1G = 1
  • 从根出发,沿 cost 最小的路径到达每个节点
  • 算法保证无环路(树天然无环)
  • 结果放进 IP 路由表

Packets

OSPF 的 5 种报文

报文类型编号作用
Hello1发现 / 维护邻居
DD (Database Description)2描述 LSDB 摘要
LSR (Link State Request)3请求缺失的 LSA
LSU (Link State Update)4发送完整 LSA
LSAck5对 LSU 的确认

Neighbors

邻居建立 · 7 个状态

  1. Down　未收到任何 Hello 包
  2. Init　收到对方 Hello,但自己不在对方列表
  3. 2-Way　双方互相在对方列表 → 邻居建立
  4. Exstart　协商主 / 从关系
  5. Exchange　交换 DD 报文(LSDB 摘要)
  6. Loading　请求缺失的 LSA(LSR / LSU)
  7. Full　LSDB 同步完成——可计算路由

Areas

OSPF 区域 · 分层设计

  • 单区域:所有路由器在 Area 0——适合小型网络
  • 多区域:有骨干区域(Backbone / Area 0)+ 常规区域
  • LSA只在区域内泛洪——区域间通过 ABR 汇总
  • 降低 LSDB 规模,加快收敛
  • 本章用单区域(全部 Area 0)
  • 大型企业用多区域(课外拓展)

PART 03

OSPF 配置与验证

3 路由器 OSPF 单区域配置。

Lab Setup

OSPF 实验 · 7 步

  1. Packet Tracer 新建 Lab16-OSPF.pkt
  2. 拖入 3 Router + 6 PC + 3 Switch
  3. 配置所有接口 IP(类似 RIP 实验)
  4. 每台路由器启动 OSPF 进程
  5. router ospf 1 → network <net> <wc> area 0
  6. 等待 40 秒——Hello 包建立邻居
  7. 验证邻居与路由表

Config

OSPF 单区域配置

R1>
R1# configure terminal R1(config)# router ospf 1 ! 进程 ID 1(本地有效) R1(config-router)# network 192.168.10.0 0.0.0.255 area 0 R1(config-router)# network 10.0.0.0 0.255.255.255 area 0 R1(config-router)# end R1# show ip ospf neighbor

Wildcard

反掩码 · 与子网掩码相反

  • 子网掩码 255.255.255.0 → 反掩码 0.0.0.255
  • 子网掩码 /24 → 反掩码 0.0.0.255
  • 子网掩码 /8 → 反掩码 0.255.255.255
  • 规则:0 = 必须匹配,255 = 任意
  • OSPF 用反掩码决定哪些接口参与 OSPF
  • 例子:network 192.168.10.0 0.0.0.255 area 0 = 192.168.10.0/24 网段参与

Verify

验证邻居 · show ip ospf neighbor

R1# show ip ospf neighbor
Neighbor ID Pri State Dead Time Address Interface 2.2.2.2 1 FULL/ - 00:00:38 10.0.0.2 Serial0/0/0

FULL = 邻居关系完全建立;左侧 IP 是邻居的 Router ID(示例 2.2.2.2 需在 R2 上配置 router-id 2.2.2.2;未手工配置时优先取最高 loopback 接口 IP,无 loopback 才取最高物理接口 IP)。

Routing Table

OSPF 路由表 · O 开头

R1# show ip route ospf
Codes: O - OSPF, IA - OSPF inter area, ... O 192.168.20.0/24 [110/65] via 10.0.0.2, Serial0/0/0 O 192.168.30.0/24 [110/129] via 10.0.0.2, Serial0/0/0 O 20.0.0.0/8 [110/128] via 10.0.0.2, Serial0/0/0

O = OSPF 学到的路由;110 = OSPF 管理距离;后面的数 = cost(沿途出接口开销之和:串口 64 + 以太网口 1;如 192.168.20.0/24 = 64 + 1 = 65)。

Router ID

Router ID · OSPF 的「身份证」

  • 32 位 IP 格式的唯一标识——同一 OSPF 域内不可重复
  • 选取规则:
    • 1. 手工配置(推荐)
    • 2. 最高 loopback IP
    • 3. 最高物理接口 IP
  • 配置:router-id 1.1.1.1(在 OSPF 进程下)
  • 建议用 loopback 接口 的 IP——稳定、不会变
  • 改 Router ID 需重启进程:clear ip ospf process

Cost

Cost · OSPF 的度量(计算)

计算 · OSPF Cost 计算(默认参考带宽 100Mbps)
01
公式 cost = 参考带宽 / 实际带宽 默认:参考 = 100 Mbps 结果取整数
02
串口 1.544M 100 / 1.544 ≈ 64 cost = 64 T1 链路
03
串口 2.048M 100 / 2.048 ≈ 48 cost = 48 E1 链路
04
以太网 10M 100 / 10 = 10 cost = 10 早期以太网

Cost

Cost · 高速链路与路径累加

计算 · 100M / 1G 与端到端 cost
01
以太网 100M 100 / 100 = 1 cost = 1 Fast Ethernet
02
以太网 1G 100 / 1000 < 1 → 1 cost = 1 最小 1
03
100M 与 1G 都 = 1 无法区分 需调整参考带宽 1000 → 1G=1,100M=10
04
北京→广州累加 R1→R2(64) + R2→R3(64) = 128 到串行网段 20.0.0.0/8 cost = 128;到广州 LAN 再加 R3 的 Fa0/0(1)= 129 走 R2 路径

Cost

Cost · 局限与调整方法

公式

cost = 参考带宽 / 实际带宽

默认参考带宽 100 Mbps:100M=1,10M=10,1G=1。

问题

1G 链路 cost=1

默认参考带宽 100Mbps 下,100M 与 1G 链路 cost 都等于 1——快链路无法区分。可手动改参考带宽(如 1000)或接口级 ip ospf cost。

配置

auto-cost reference-bandwidth

真实 IOS:auto-cost reference-bandwidth 1000(PT 6.2 不支持,请用接口级 ip ospf cost)

接口级

ip ospf cost

接口下直接指定:ip ospf cost 5

Case 01

案例 · 邻居卡在 INIT

故障现象

R1 与 R2 OSPF show ip ospf neighbor 显示状态 INIT,不是 FULL。

诊断

步骤 1:两端接口是否 UP?

步骤 2:区域号是否一致?(区域号不一致邻居会停在 DOWN,而非 INIT)

步骤 3:子网掩码是否一致?

步骤 4:是否有 ACL 阻塞 OSPF 报文(协议 89)?

解决

INIT = 收到过对方 Hello,但自己的 Router ID 不在对方 Hello 中——多为单向可达、组播被过滤或认证不匹配;area 号不一致则邻居停在 DOWN(或邻居表为空)。

结论

✅ OSPF 邻居建立必须:Area 一致 + 接口 UP + 掩码一致 + Hello/Dead 计时器一致 + 认证匹配。
