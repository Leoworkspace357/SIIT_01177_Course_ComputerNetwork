Scenario

任务情境 · 学院网站上线

人物

小王

某学院网络中心的一名网络管理员。

需求

发布学院网站

需要将学院网站发布出去，让师生与外界都能访问。

目标

好记的域名

通过输入 www.siit.cn 这样的域名就能访问——而不是一串 IP。

解决方案

WWW + DNS

搭建 WWW（Web）服务 + DNS（域名解析）服务。

Goal

任务目标

目标

域名访问

通过 IE 地址栏输入 http://www.siit.com 就能访问网站——方便记忆。

核心

域名 ↔ IP

把「域名」与「IP 地址」对应起来——靠 DNS 服务器完成映射。

组成

WWW + DNS

WWW 服务器提供网页内容；DNS 服务器提供域名解析。

价值

贴近用户

这是应用层最贴近用户的两大服务——也是网络「可用性」的最后一公里。

Environment

使用环境

服务器

WWW + DNS 一体

一台 Windows Server 服务器，同时运行 WWW 与 DNS 服务。

服务器 IP

192.168.1.1

服务器 IP：192.168.1.1；网站存放默认 Web 主目录。

客户机

Windows

客户机安装 Windows 系统，IP = 192.168.1.2，与服务器连通。

验证

域名访问

客户机浏览器输入 http://www.siit.com 应能打开服务器上的网页。

Background

相关知识

层次型命名、因特网域名与 DNS 解析。

Naming

层次型命名机制

结构

树状结构

层次型命名采用树状结构——树的每一节点都有相应的标识符。

主机名

路径序列

主机名 = 从树叶到树根（或反向）路径上各节点标识符的有序序列。

例子

www.siit.cn

www.siit.cn —— cn（根）→ siit → www（叶子主机）。

价值

唯一 + 分层

全球唯一 + 分层管理——不同后缀由不同机构管理。

TLD

因特网顶级域名

组织模式

通用顶级域

.com / .org / .net / .gov / .edu / .mil / .int　按组织性质分配。

地理模式

国家顶级域

.cn / .us / .jp / .uk / .de　按国家或地区分配，每个国家独立管理。

新增

新型顶级域

.app / .io / .dev / .ai / .xyz　近年开放的新型 gTLD。

管理者

ICANN

顶级域名由 ICANN 统一管理；国家域由各国 NIC 管理。

中国二级域名示例

类别二级域名用途
类别域名.com.cn工商企业
类别域名.net.cn网络服务
类别域名.gov.cn政府机构
类别域名.edu.cn教育机构
类别域名.org.cn社会组织
行政区域.bj.cn / .sh.cn / .gd.cn北京 / 上海 / 广东等

DNS Intro

DNS 简介

全称

Domain Name System

DNS 是域名系统（Domain Name System）的缩写——一种组织域层次结构的命名系统。

作用

名字 → 地址

计算机在网络上使用 IP 地址通信；DNS 把用户使用的「名称」映射为「IP 地址」。

类比

电话簿

DNS 就是互联网的「电话簿」——输入名字就能查到电话号码。

协议

UDP 53 / TCP 53

DNS 主要使用 UDP 53 端口；区域传送等用 TCP 53。

Resolution

DNS 解析 · 工作流程

01

查询请求

客户端向本地域名服务器发起查询——「www.siit.cn 的 IP 是多少？」

02

递归 / 迭代

本地域名服务器递归询问根服务器、cn 服务器、siit.cn 服务器……

03

返回结果

最终把解析结果返回给客户端，并缓存下来。

04

访问网站

客户端拿到 IP，向该 IP 发起 HTTP 请求——完成 WWW 访问。

Query Methods

DNS 查询方式 · 两种

递归

Recursive

客户端 → 本地 DNS：要求「必须给我最终答案」，由本 DNS 服务器代为查询。

迭代

Iterative

本地 DNS → 根 / 顶级 / 权威 DNS：每次返回「下一级去找谁」，本地 DNS 自行迭代查询。

结合

递归 + 迭代

实际是递归查询 + 迭代查询的组合：客户端递归，本地 DNS 迭代。

缓存

Cache

各级 DNS 都会缓存结果——TTL 时间内再次访问无需重新查询。

Terms

DNS 中的常见名词

术语含义
正向查找区域FQDN → IP　把域名解析为 IP 地址
反向查找区域IP → FQDN　把 IP 反查为主机名
主要区域包含相应 DNS 命名空间所有的资源记录
存根区域仅包含权威 DNS 服务器的记录，用于委派解析
资源记录（RR）A / AAAA / CNAME / MX / NS / SOA / PTR / TXT 等
TTLTime To Live　缓存记录的存活时间

Wrap-up

本章总结 · WWW 与 DNS

WWW

Web 服务

HTTP / HTTPS 提供网页内容——把服务器上的文件返回给浏览器渲染。

DNS

域名解析

把域名翻译为IP 地址——互联网的「地址簿」。

协作

完整流程

输入域名 → DNS 解析拿到 IP → 浏览器向该 IP 发 HTTP 请求 → 服务器返回网页。

进阶

延伸

负载均衡、CDN、Anycast DNS 等都是基于 DNS 与 WWW 的工程演进。

Recap

本章小结

  1. WWW　万维网服务，通过 HTTP 把网页内容送达浏览器
  2. DNS　把域名解析为 IP 地址，支撑「好记的网址」
  3. 层次型命名　树状结构，从根到叶子逐级定位
  4. 查询方式　递归查询 + 迭代查询 + 缓存
  5. 记录类型　A / AAAA / CNAME / MX / NS / SOA / PTR / TXT
  6. 课程小结　17 章覆盖 LAN / WAN / VLAN / 路由 / 应用服务——完成整个「计算机网络」入门闭环
