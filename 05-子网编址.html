PART 01

任务一 · 认识子网

为什么分类 IP 不够用？怎么划分子网？

Why Subnets

为什么要划分子网？

问题

C 类也浪费

随着个人电脑普及，中小型网络越来越多；即使是 C 类地址，大多数情况下也会浪费大部分地址。

根源

分类太死板

A 类给 1677 万台不够分配，B 类给 6.5 万台又太多——「一个网段只能是一个 size」。

方案

划分子网

从主机号部分借位当作子网号——一个 C 类可分成多个小子网。

好处

提高利用率

每个子网大小正合适，减少浪费；同时隔离广播域，提升性能。

How

怎么划分子网？

  1. 将 IP 地址的主机号部分进一步划分为 子网号 + 主机号
  2. 从主机号部分「借」 k 位，指定为子网号
  3. 子网号所占位数越多，每个子网可容纳的主机越少
  4. 至少借 2 位　避免全 0 / 全 1 的无效子网号
  5. 主机号至少留 2 位　每个子网至少 2 台可用主机

Visual

「借位」的过程 · C 类 /26

以 C 类 192.168.1.0 借 2 位为例——32 位二进制：

Reserved

子网中的特殊地址

规则

子网号全 0 / 全 1

二进制全「0」或全「1」的子网号不能分配给任何子网。

子网地址

主机号全 0

以主机号二进制全「0」结尾——代表「这一个子网」。

子网广播

主机号全 1

以主机号二进制全「1」结尾——向该子网所有主机广播。

有限广播

32 位全 1

255.255.255.255　广播被限制在本地物理网络。

PART 02

任务二 · 子网掩码

怎么从 IP 还原出网络地址？答案——「按位 AND」。

Mask

什么是子网掩码？

  • 子网掩码采用32 位二进制　与 IP 一一对应
  • 与 IP 的网络号 + 子网号对应的位用 「1」
  • 与 IP 的主机号对应的位用 「0」
  • 结合 IP + 掩码 → 判断网络号、子网号、主机号
  • 把 IP 与掩码按位 AND，得到的就是网络地址

Default Masks

标准 IP 地址的子网掩码

PART 03

案例 · 动手算子网

从「给出 IP + 掩码」到「算出子网范围」的完整过程。

Case 01

案例 1 · B 类 /24 借 8 位

题目

已知 IP = 172.25.17.51，子网掩码 = 255.255.255.0。求该主机所在的子网、主机范围与广播地址。

步骤 1 · 求网络地址

IP AND 掩码 → 172.25.17.0　·　子网号 = 17

步骤 2 · 求主机范围

网络地址 + 1 到广播地址 − 1 → 172.25.17.1 – 172.25.17.254

步骤 3 · 求广播地址

网络地址 + 主机位全 1 → 172.25.17.255

结论

✅ 子网 172.25.17.0/24　·　可用主机 254 台　·　广播 172.25.17.255

Case 02

案例 2 · B 类 /20 借 4 位

题目

已知 IP = 172.25.17.51，子网掩码 = 255.255.240.0。求子网、范围、广播。

步骤 1 · 分析借位

B 类原始 /16，借 4 位 → /20。第 3 字节高 4 位为子网号，低 4 位为主机号。

步骤 2 · 求网络地址

第 3 字节 17 = 0001 0001，AND 掩码 1111 0000 → 0001 0000 = 16　·　网络地址 = 172.25.16.0

步骤 3 · 求主机范围

第 3 字节剩余 4 位 = 0–15 (12 跳过) → 172.25.16.1 – 172.25.31.254　·　可用主机 4094 台

步骤 4 · 求广播地址

主机位全 1 → 第 3 字节 = 0001 1111 = 31　·　广播 = 172.25.31.255

结论

✅ 子网 172.25.16.0/20　·　可用主机 4094 台　·　广播 172.25.31.255

Case 03

案例 3 · C 类 /29 借 5 位

题目

已知 IP = 192.168.5.121，子网掩码 = 255.255.255.248。求子网、范围、广播。

步骤 1 · 分析借位

C 类原始 /24，借 5 位 → /29。第 4 字节高 5 位为子网号，低 3 位为主机号。

步骤 2 · 求网络地址

第 4 字节 121 = 111 1001，AND 掩码 11111 000 → 111 1000 = 120　·　网络地址 = 192.168.5.120

步骤 3 · 求范围与广播

主机位 3 位 → 8 个地址（去掉全 0、全 1 = 6 台）　·　范围 192.168.5.121 – 192.168.5.126　·　广播 192.168.5.127

结论

✅ 子网 192.168.5.120/29　·　可用主机 6 台　·　广播 192.168.5.127

Case 04

案例 4 · 同 IP 不同掩码

题目

主机 A 配置 192.168.1.1/30，主机 B 也配 192.168.1.1/24。它们能直接通信吗？

分析 · 主机 A

192.168.1.1 AND 255.255.255.252 = 192.168.1.0/30　·　可用主机 2 台

分析 · 主机 B

192.168.1.1 AND 255.255.255.0 = 192.168.1.0/24　·　可用主机 254 台

解读

主机 A 认为自己属于 192.168.1.0/30　·　主机 B 认为自己属于 192.168.1.0/24

实际两个子网在逻辑上不同（A 范围 0–3，B 范围 0–255）——会失败

结论

❌ 无法直接通信——即使 IP 相同，掩码不同就视为不同子网。两端必须使用相同掩码。

PART 04

回顾与展望

子网编址解决了「分类浪费」的问题，但 B 类借位、C 类子网表——「繁琐」催生了 CIDR。

Pros & Cons

子网编址的优缺点

优点

提高利用率

不再受分类限制——按需分配子网大小，减少 IP 浪费。

优点

隔离广播

每个子网是独立广播域，减少网络风暴。

优点

便于管理

可按部门 / 楼层 / 业务划分——「结构化」清晰。

缺点

仍繁琐

仍要算二进制、记表格——下一章 CIDR 会大幅简化。

Recap

本章小结

  1. 子网编址：主机号部分借位作子网号
  2. 借位规则：k ≥ 2（避免全 0/全 1），主机 ≥ 2 位
  3. C 类最多借 6 位 → 62 个子网；B 类最多借 14 位 → 16382 个子网
  4. 子网掩码：网络/子网位为 1，主机位为 0
  5. 按位 AND：IP AND 掩码 = 网络地址
  6. 同一子网判定：网络号必须相同
