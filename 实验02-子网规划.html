BG · 01

实验背景

某公司有 4 个部门：行政（10 人）、研发（30 人）、市场（50 人）、财务（20 人），合计 110 人。公司从运营商获得一段公网地址 192.168.100.0/24，现要求：

1. 把 192.168.100.0/24 划分为 4 个等长子网（每个子网最多 64 台主机）。 2. 每个部门使用一个子网，并在 Packet Tracer 中模拟。 3. 各子网之间通过路由器互通。

STEP 01.1

借位分析

需要 4 个子网 → 至少 2 位子网号（2^2 = 4）。

原始 /24 → 借 2 位 → 新掩码 /26 = 255.255.255.192。

每个子网主机位 = 32 - 26 = 6 → 最多 2^6 - 2 = 62 台主机 ✓（满足 ≤ 64 人的需求）。

BG · 02

背景 · 子网划分原理

借位：从主机位借 N 位作子网号；N 位可分 2^N 个子网（去全 0/全 1）。

主机位：32 - 原前缀 - 借位数；可用主机 = 2^主机位 - 2（去网络地址 + 广播地址）。

子网掩码：网络号 + 子网号对应位为 1，主机号对应位为 0。

BG · 03

背景 · Router-on-a-Stick

通过单条物理链路 + 802.1Q Trunk + 子接口承载多个 VLAN / 子网的路由。

优点：节省路由器端口。

缺点：单链路瓶颈（实验环境下够用）。

STEP 02.5

配置交换机的 VLAN 与 Trunk

  • SW0 → CLI，创建 VLAN 1、VLAN 10、VLAN 20、VLAN 30 并命名。
  • 将 Gi0/1 配置为 Trunk 模式（接 SW1）。
  • 将 Gi0/2 配置为 Trunk 模式（接 R0）。
  • 把 PC0 接入的端口划入 VLAN 1（行政）。
  • PC1 接入的端口划入 VLAN 10（市场）；SW1 上的 PC2 → VLAN 20、PC3 → VLAN 30。
  • 配置完成后 end; write memory。

STEP 02.7

验证子网配置

  • 在每台 PC 上 → Desktop → Command Prompt：ipconfig。
  • 确认 IP、子网掩码、网关正确。
  • 在 R0 CLI：show ip interface brief — 应看到 5 个 UP 接口（Fa0/0 + 4 个 sub-if）。
  • show ip route — 应看到 4 条直连路由（行政 / 研发 / 市场 / 财务）。
STEP 02.8

测试跨子网连通性

  • PC0 ping PC1（行政 → 市场）：应通；TTL ≈ 126。
  • PC0 ping PC2（行政 → 研发）：应通。
  • PC0 ping PC3（行政 → 财务）：应通。
  • PC2 ping PC3（研发 → 财务）：应通。
  • 注意：跨路由器子接口转发一次，TTL 减 1（TTL 由 128 → 126 → 124）。

ERR · 01

常见错误与排错

PC 不能 ping 通网关

子网掩码错 / 网关错 → 重新核对 ipconfig。

同子网内能 ping，跨子网不通

路由器子接口未 no shutdown → 检查 R0 CLI 中 show ip interface brief。

跨子网时通时不通

Trunk 配置丢失 → 确认 SW0/SW1 的 Gi0/1、Gig0/2 都是 trunk。

Simulation 中显示「Encapsulation failure」

子接口的 VLAN ID 与交换机不一致 → 检查 encapsulation dot1Q N 的 N。
