任务情境 · 打开一个网页

Scenario

输入 URL 到看见网页 · 8 步

  1. 浏览器解析 URL:https://www.baidu.com/
  2. 浏览器查 DNS:www.baidu.com → 110.242.68.66
  3. 浏览器与服务器TCP 三次握手(端口 443 / 80)
  4. 如果是 HTTPS → TLS 握手
  5. 浏览器发送 HTTP GET / 请求
  6. 服务器返回 HTTP 200 OK + HTML
  7. 浏览器解析 HTML / CSS / JS,加载图片
  8. 渲染完成 — 你看到网页

PART 02

WWW 原理

World Wide Web = 全球超文本系统。

WWW

WWW 的 4 个核心概念

URL

统一资源定位符

Uniform Resource Locator——网页的「地址」。

HTTP

超文本传输协议

HyperText Transfer Protocol——浏览器与服务器对话的规则。

HTML

超文本标记语言

HyperText Markup Language——网页的内容。

URL 三段

协议 + 主机 + 路径

https://www.baidu.com/news——协议/主机/路径。

HTTP Methods

HTTP 方法 · 5 种

GET

读取

从服务器读取资源——如打开网页。

POST

提交

向服务器提交数据——如登录、评论。

PUT

更新

更新资源(整体替换)。

DELETE

删除

删除资源。

HEAD

元信息

只获取头部(类似 GET 但不返正文)。

状态码

200 / 404 / 500

200 成功;404 未找到;500 服务器错。

HTTP Demo

HTTP 请求 / 响应 · 真实报文

$ curl -v http://www.baidu.com/
> GET / HTTP/1.1 > Host: www.baidu.com > User-Agent: curl/7.79.1 > Accept: */* < HTTP/1.1 200 OK < Server: BWS/1.1 < Content-Type: text/html; charset=utf-8 < Content-Length: 12345 < Connection: keep-alive <html>...</html>

WWW Server

搭建 WWW 服务器 · 4 步

  1. 安装 Web 服务器(IIS / Apache / Nginx)
  2. 创建 网站目录(如 C:\inetpub\wwwroot)
  3. 放置网页文件 index.html
  4. 浏览器访问 http://localhost 或 http://<server-ip>

PART 03

DNS 原理

把 www.baidu.com 翻译成 110.242.68.66。

DNS

DNS · 域名系统

作用

域名 → IP

把人类易记的域名解析为机器识别的 IP 地址。

端口

UDP/TCP 53

DNS 默认用 UDP 53(小响应);大响应切 TCP 53。

分层

树状结构

根 → 顶级域 → 二级域 → 子域——全球 13 组根服务器。

Domain

域名空间 · 树状结构

www.baidu.com 从右向左解析:根 → com → baidu → www。

Query

DNS 查询 · 耗时估算

计算 · DNS 查询总耗时估算
01
本地 DNS 缓存查询 ~1 ms(命中) 0 次网络查询 最快情况
02
本地 DNS 递归查询 本地 → 根(20ms) → .com 顶级域(30ms) → baidu.com 权威(50ms) = ~100 ms 首次访问
03
TCP 三次握手 1 × RTT ≈ 50ms（客户端视角：SYN → SYN-ACK 往返一次） 客户端 ↔ 服务器 建立连接
04
TLS + HTTP(HTTPS 访问) TLS 2×RTT = 100ms;HTTP ~50ms + 资源 × N 合计 150–500ms 取决于页面大小与证书协商
05
总耗时 首次访问 200–500ms 缓存命中 50–200ms CDN 后可降至 50ms

Query

DNS 查询 · 8 步流程

  1. 客户端问 本地 DNS(如 8.8.8.8):www.baidu.com?
  2. 本地 DNS 查缓存 → 有则直接返回
  3. 本地 DNS 问 根:.com 谁管?
  4. 根返回 .com 顶级域服务器 地址
  5. 本地 DNS 问 .com 服务器:baidu.com 谁管?
  6. 返回 baidu.com 权威 DNS
  7. 本地 DNS 问权威 DNS:www.baidu.com 的 IP?
  8. 返回 110.242.68.66 给客户端

Recursive vs Iterative

递归 vs 迭代查询

递归

客户端 → 本地 DNS

客户端问本地 DNS,本地 DNS 一查到底;

客户端只发一次请求。

迭代

本地 DNS → 各级

本地 DNS 自己逐级询问根、com、baidu.com;

每次问一个,得到下一个地址。

Records

DNS 记录类型 · 8 种

类型作用示例
A域名 → IPv4www.baidu.com → 110.242.68.66
AAAA域名 → IPv6www → 2001:da8::1
CNAME别名www → baidu.com
MX邮件服务器baidu.com → mx.qq.com
NS权威 DNSbaidu.com → ns1.baidu.com
TXT文本记录SPF / DKIM / 验证
PTRIP → 域名(反向)反查
SOA起始授权区域起始记录

Hierarchy

DNS 层次 · 全球 13 组根

  • 根服务器:全球 13 组(A-M),由 12 个机构运营
  • 顶级域(TLD):.com .org .net .cn .edu……
  • 权威 DNS:每个域名(如 baidu.com)有至少 2 台 权威服务器
  • 本地域名服务器(Local DNS):用户配置的递归解析器
  • 客户端 → 本地 DNS(递归);本地 DNS → 各级(迭代)

Lab DNS

实验 · Windows DNS 配置

C:\> dnscmd
C:\> dnscmd /ZoneAdd corp.local /Primary Zone corp.local created. C:\> dnscmd /RecordAdd corp.local www A 192.168.10.50 A record added. C:\> dnscmd /RecordAdd corp.local mail A 192.168.10.60 A record added. C:\> nslookup www.corp.local 192.168.10.1 Server: corp-dns.corp.local Address: 192.168.10.1 Name: www.corp.local Address: 192.168.10.50

HTTPS

HTTPS · 加密的 HTTP

  • HTTPS = HTTP + TLS(SSL 已弃用)
  • 默认端口 443(HTTP 是 80)
  • TLS 握手:客户端与服务器交换证书、协商密钥
  • 建立对称加密通道——后续数据传输加密
  • 证书由 CA(证书颁发机构)签发
  • 自签名证书:浏览器会警告(企业内部可用)
  • HTTPS 是趋势——现代网站默认 HTTPS

Case 01

案例 · DNS 解析失败

故障现象

浏览器输入 www.corp.local → 「无法找到此页面」,但直接 IP 可访问。

诊断

步骤 1:本机 DNS 配置 — 是否指向 DNS 服务器?

步骤 2:DNS 服务器上是否有 corp.local 区域?

步骤 3:区域中是否有 www 的 A 记录?

解决

本机 DNS 指向 192.168.10.1;区域添加 www → 192.168.10.50。

结论

✅ DNS 解析失败:链路任意一环出错就解析不出。

Case 02

案例 · HTTP 500 错误

故障现象

访问网站返回 HTTP 500 Internal Server Error。

诊断

步骤 1:看服务器日志(IIS 日志 / Apache error.log)

步骤 2:常见原因 — 代码语法错、权限不足、数据库连接失败

解决

根据日志定位具体错误——通常是 代码 bug 或 配置问题。

结论

⚠️ 500 是服务器内部错误,与客户端无关。

Misconceptions

常见误解 · 别踩坑

  • 「DNS 解析 = 自动」——部分对。DNS需要配客户端和服务器。
  • 「域名就是网址」——错。域名是主机名,URL 还包含协议、路径。
  • 「HTTP = Web」——部分对。HTTP 也用于 API、文件下载等。
  • 「DNS 只走 53 端口」——不。除 53 外还有 DoH(443)、DoT(853)、mDNS(5353)。
  • 「所有网站都要 HTTPS」——趋势。HTTP 仍可用,但浏览器会警告。
