任务情境 · 公司又慢了

换成交换机后,网络变快,但又有新的麻烦——

Scenario

从公司成立到网络改造

扩张

规模扩大

Alice 与 Bob 的公司规模越来越大,部门越来越多。

症状

传输越来越慢

老员工纳闷:计算机配置越来越高,文件传输却越来越慢。

诉求

网络改造

网络改造的呼声越来越高——如何优化、解决拥堵?

答案

VLAN

把一个大的广播域切成多个小的逻辑网络,让广播范围可控。

Why VLAN

为什么换 Switch 后还慢?

交换机的局限

广播域未隔离

Switch 解决了冲突但没解决广播——所有 PC 仍在同一广播域。

广播数量

100 台 = 100 个广播源

每台 PC 都会发送 ARP / DHCP / 路由通告等广播——人数越多,广播越密集。

影响

带宽浪费

广播包全员接收——99% 的主机不需要这些包,但仍要处理。

隐私

广播可被监听

某些广播包携带敏感信息——同网内任何主机都能嗅探。

VLAN Solution

VLAN · 广播域的手术刀

原理

逻辑分割

VLAN 在同一台物理 Switch 上划分出多个独立广播域——物理上一台,逻辑上多台。

效果

隔离广播

VLAN A 的广播包不会传到 VLAN B——广播范围受控。

优势

灵活 + 安全

按部门/职能/项目划分 VLAN——网络更整洁,部门间「天然隔离」。

经济

无需更多设备

不需要为每个部门买一台 Switch——一台支持 VLAN 的 Switch 即可。

PART 02

VLAN 原理

Switch 怎么「认出」一帧属于哪个 VLAN?

What is VLAN

VLAN 的本质

定义

虚拟局域网

Virtual Local Area Network——在物理 LAN 上划分出逻辑独立的小 LAN。

本质

同一广播域

同一 VLAN 的设备共享广播;不同 VLAN 互不干扰。

编号

VLAN ID

每个 VLAN 有唯一 ID (1-4094);VLAN 1 是默认,通常用于管理。

Division

VLAN 划分方式 · 3 种

方式依据优点缺点
基于端口交换机端口号简单直观主机换端口要重配
基于 MAC主机 MAC 地址主机移动自动跟随MAC 数量大,管理复杂
基于 IP / 协议IP 子网或协议类型灵活依赖网络层信息

实际工程中基于端口最常用——简单可靠。

Access vs Trunk

Access 端口 vs Trunk 端口

Access

接入端口

连接终端设备(PC、服务器);

只属于一个 VLAN;

发出帧不带 VLAN 标记。

Trunk

中继端口

连接其他 Switch / 路由器;

可承载多个 VLAN;

发出帧带 VLAN 标记(802.1Q)。

802.1Q

802.1Q 帧标记 · 结构拆解

计算 · VLAN ID 与 802.1Q Tag
01
VLAN ID 范围 12-bit 字段 0–4095(共 4096 个) 0 和 4095 通常保留
02
可用 VLAN 1–4094 4094 个可用 VLAN ID 默认 VLAN = 1
03
802.1Q Tag 位置 在以太网帧的 SA 之后、Type 之前 插入 4 字节标签 0x8100 表示 802.1Q
04
TPID(2 字节) 0x8100 = 802.1Q 标记 类型标识 0x88a8 = 802.1ad QinQ

802.1Q

802.1Q 帧标记 · 要点总结

计算 · TCI 字段与 Native VLAN
01
TCI(2 字节) 3 bit Priority + 1 bit DEI + 12 bit VLAN ID 实际承载 VLAN 信息 802.1Q 核心
02
例:VLAN 10 0000 0000 0000 1010 Priority=0, DEI=0, VID=10 最大 4094
03
Native VLAN 在 Trunk 上不打标签 默认 VLAN 1 建议改为未使用 VLAN(如 99)
  • 802.1Q 是VLAN 的国际标准(IEEE)
  • 在以太网帧中插入 4 字节的 VLAN 标签
  • 标签里包含 12-bit VLAN ID——支持 4094 个 VLAN
  • 除 Native VLAN 外,Trunk 上的帧都带标签,接收端 Switch 据此识别帧属于哪个 VLAN
  • 从 Access 端口发出时剥掉标签——终端设备看不到

Native VLAN

Native VLAN · 特殊的 Trunk 概念

  • Trunk 链路默认有一个 Native VLAN(通常是 VLAN 1)
  • Native VLAN 的帧在 Trunk 上不打标签
  • 主要用于兼容老设备、CDP / VTP 等管理协议
  • 安全建议:实际工程中把 Native VLAN 改成一个不使用的 VLAN(如 VLAN 99)
  • 两端 Switch 的 Native VLAN 必须一致,否则会丢包

Broadcast Domain

VLAN 前后 · 广播域对比

未划 VLAN

一个广播域

整个 Switch = 1 个广播域

100 台 PC = 100 个广播源

→ 任何人广播,全员处理

划 VLAN 后

多个广播域

1 台 Switch = N 个广播域

每个 VLAN 「独立」互不干扰

→ 广播范围被 VLAN 切割

Benefits

VLAN 的 5 大优势

  • 限制广播:每个 VLAN 是独立广播域,广播包不外泄
  • 提高安全:不同 VLAN 默认隔离,减少嗅探风险
  • 灵活管理:按部门/项目划分,逻辑清晰
  • 降低成本:不用为每个部门买物理 Switch
  • 便于扩展:新增主机只需划入对应 VLAN,无需改物理布线

Task 01

任务一 · 创建 VLAN

目标

划分 4 个 VLAN

在 Switch 上创建 VLAN 10 (研发)、VLAN 20 (销售)、VLAN 30 (财务)、VLAN 40 (人事)。

命令

configure terminal → vlan <ID>

进入全局配置模式,在 vlan <ID> 子模式下创建 VLAN(现代 Cisco IOS 标准)。

示例

vlan 10 name RD

创建 VLAN 10,名称为 RD (Research & Development)。

验证

show vlan

用 show vlan 查看已创建的 VLAN 列表。

Task 02

任务二 · 端口划分到 VLAN

进入端口

interface fa0/1

进入需要配置的端口(以 Fa0/1 为例)。

设模式

switchport mode access

设为 access 模式——只能属于一个 VLAN。

分配 VLAN

switchport access vlan 10

将 Fa0/1 划到 VLAN 10 (RD)。

验证

show vlan brief

用 show vlan brief 查看端口归属。

Limits

VLAN 的局限 · 客观看待

  • VLAN 间不能直接互通——需要三层设备(路由器或三层交换机)
  • 不同 VLAN 必须使用不同的 IP 子网
  • Trunk 链路如果出现故障,可能造成 VLAN 「单通」
  • 交换机之间的 Trunk 配置要一致——管理复杂
  • 无线 AP 接入 VLAN 需要特殊配置(如 VLAN 标签)

VLAN vs Subnet

VLAN vs 子网 · 一表对比

维度VLAN子网
工作层次二层(数据链路)三层(网络)
标识VLAN ID (1-4094)子网掩码(/24 等)
分隔内容广播域IP 子网
互通方式需要路由器/三层交换机需要路由器
关系通常一一对应通常一一对应

VLAN + 子网 通常成对设计——一个 VLAN 一个 /24 子网。

Case 01

案例 1 · 划 VLAN 后跨网段不通

故障现象

Alice 在 VLAN 10 配置 IP 192.168.10.1/24,Bob 在 VLAN 20 配置 IP 192.168.10.2/24(应是 192.168.20.2/24),ping 不通。

诊断

不同 VLAN 不能使用同一子网——VLAN 隔离广播域,IP 也必须不同。

解决

把 Bob 的 IP 改为 192.168.20.2/24——VLAN 20 对应子网 20。

补充

即使改对了子网,不同 VLAN 间仍不通——需要三层设备(路由器或三层交换机),详见下一章。

结论

✅ VLAN 一一对应子网是规划的基本原则;但仅同 VLAN可直接互通。

Case 02

案例 2 · 两台 Switch 间 VLAN 不通

故障现象

两台 Switch 用 Fa0/24 互连,SW1 的 VLAN 10 上的 PC 与 SW2 的 VLAN 10 上的 PC ping 不通。

诊断

互连链路两端 Access VLAN 不一致(对端仍为默认 VLAN 1)——同一 VLAN 的帧无法通行。

解决

先核对两端 access VLAN 一致;若该链路要承载多个 VLAN,则把 Fa0/24 改为 Trunk 模式:

interface fa0/24 → switchport mode trunk

结论

✅ Switch 之间的链路必须用 Trunk 才能承载多个 VLAN。

Case 03

案例 3 · 端口模式错配

故障现象

PC 接在 Fa0/5,配置 Trunk 模式(本应是 Access)——ping 同 VLAN 其他主机不通。

诊断

PC 默认不发送 802.1Q 标签。Trunk 口收到未打标签的帧会归入 Native VLAN（默认 VLAN 1）——PC 实际落入了 VLAN 1，所以与 VLAN 10 的主机不通。

解决

把 Fa0/5 改回 switchport mode access——终端必须接 Access 端口。

结论

⚠️ 端口模式决定帧的处理方式——Access 和 Trunk 不能混用。

Misconceptions

常见误解 · 别踩坑

  • 「VLAN 隔离 = 物理隔离」——错。只是二层隔离,三层仍可互通。
  • 「VLAN 可以用同一子网」——错。不同 VLAN 必须不同子网。
  • 「Trunk 比 Access 快」——错。Trunk 只多 4 字节标签,可忽略。
  • 「VLAN 增加安全性」——部分对。隔离了广播,但数据仍可监听(除非加密)。
  • 「VLAN ID 越大越优先」——错。VLAN ID 无优先级,1-4094 都是普通编号。
