PART 01

为什么需要 IP 地址？

MAC 地址已经能唯一标识网卡，为什么还要 IP？

Problem

MAC 地址不够用

问题

物理地址各异

每种物理网络都有各自的技术特点，MAC 地址各不相同——以太网、Wi-Fi、令牌环……

困境

难以统一

统一物理地址的表示方法不现实——历史包袱 + 各厂商利益。

方案

IP 层统一

在 IP 层用统一的地址方案屏蔽底层物理差异。

本质

逻辑地址

IP 地址是面向网络的逻辑地址，与具体硬件无关。

Function

IP 地址的 4 个作用

  • 指定计算机到互联网的一个连接
  • 多接口设备（路由器、多宿主主机）具有多个 IP
  • 多个 IP 可以绑定到一条物理连接上
  • IP 地址本质上标识网络接口，而不是机器本身
CASE · 多接口设备的 IP 数量

一台家用路由器通常有 2 个接口：WAN 口（公网 IP，比如 110.242.68.66）和 LAN 口（私网 IP，比如 192.168.1.1）。它同时拥有两个 IP。

一台服务器绑定了多个网站？可以用同一个网卡的不同 IP，对外呈现多个站点。

32 位二进制与点分十进制

人类读不懂 32 位连续 0/1，所以发明了点分十进制。

每 8 bit 转换为 0–255 的十进制，用「.」隔开——这叫点分十进制（dotted-decimal）。

Range

为什么是 0–255？

  • 8 位二进制最大 = 11111111 = 十进制 255
  • 最小 = 00000000 = 0
  • 范围 0–255，共 256 个值
  • 所以 192.168.1.256 是非法的（256 越界）
  • 常见合法范围：家庭 192.168.1.1–192.168.1.254

PART 03

IP 地址的五类划分

32 位中前几位决定类别——这是历史遗留的「分蛋糕」方式。

Hierarchy

netid + hostid 的两层结构

netid

网络号

标识互联网中一个特定的网络。由上级机构（IANA / 区域注册机构）分配。

hostid

主机号

标识该网络中的一个特定连接（网络接口）。由网络管理员分配。

类比

楼号 + 房间号

netid = 楼号；hostid = 房间号——同一个网络就像同一栋楼。

好处

路由聚合

路由器只记楼号就能转发，不必为每个房间单独建表。

Hierarchy

互联网的三层结构

顶层互联网 Internet若干自治系统
中层自治系统 / 网络若干子网
底层子网 / 物理网络若干主机

IP 地址的网络号对应上面两层，主机号对应最底层的主机。

Classes

A / B / C / D / E 五类地址

前几位的不同，决定地址类别。

A 类 0 网络号 8 位 主机号 24 位
B 类 10 网络号 16 位 主机号 16 位
C 类 110 网络号 24 位 主机号 8 位
D 类 1110 组播地址
E 类 1111 实验保留

Why Classes

为什么要分类？

优点

适应不同规模

A 类 1677 万 / B 类 6.5 万 / C 类 254 —— 大中小网络各有归属，避免浪费。

优点

路由简单

路由器读 netid 就能判断往哪转，不必关心主机号。

优点

聚合能力强

路由表中只记网络号，可聚合大量主机到一条路由。

缺点

不够灵活

C 类只有 254 台——不够？B 类又能给 6.5 万台——太大；「中间没合适的」。

这个问题的解决：子网划分 + CIDR——下一章讨论。

PART 04

特殊的 IP 地址

除了普通主机地址，IP 还有一些具有特殊含义的地址。

Special · Net

网络地址 · 标识整个网络

构成

全「0」主机号

一个有效的网络号 + 全「0」的主机号。

含义

代表一整个网络

「这一整个网络」——不分配给任何主机。

举例

202.93.120.0

主机 202.93.120.44 所在的网络地址就是 202.93.120.0。

用法

路由表项

网络地址出现在路由表中——「到这一网络的路径」。

Special · Broadcast

广播地址 · 一呼百应

直接广播

网络号 + 全「1」

主机向其他网络的所有节点广播信息。需要知道目的网络的网络号。

例

202.93.120.255

向 202.93.120.0 网络上的所有主机发送数据。

有限广播

255.255.255.255

不需知道网络号，广播被限制在本地物理网络。

用途

DHCP · ARP

DHCP 自动获取 IP、ARP 解析 MAC 都依赖广播。

Special · Loopback

回送地址 · 127.0.0.0/8

范围

127.0.0.0 – 127.255.255.255

整个 127.0.0.0/8 网段都被保留为回送地址，最常用 127.0.0.1。

作用

协议栈测试

用于测试本机的 TCP/IP 协议栈是否正常工作。

作用

本机进程通信

同一台机器上的客户端 / 服务端可通过 127.0.0.1 通信——数据库、Web 开发常用。

特性

不出现在网络上

任何含网络号 127 的数据报永远不会出现在真实网络中。

CASE · 启动 Web 服务器

开发 Node.js / Python Flask 时，你访问 http://localhost:3000——其实就是在访问 127.0.0.1:3000。数据根本不会离开你的电脑。

Special · Private

私有 IP · 内网专用

10.0.0.0/8

A 类私有

1 个 A 类网段，1677 万 个地址——大企业内网。

172.16.0.0/12

B 类私有

16 个 B 类网段，约 104 万 个地址——中型企业。

192.168.0.0/16

C 类私有

256 个 C 类网段，6.5 万 个地址——家庭、小公司。

这些地址不会出现在公网，通过 NAT 共享一个公网 IP 上网。

PART 05

案例 · 判断「同一网络」

动手算一算——两台主机的网络号相同，就在同一个网络。

Case 01

案例 1 · 同一 C 类网段

题目

222.1.1.111 与 222.1.1.89　属于同一个网络吗？属于哪一类？

分析

① 首字节 222 ∈ [192, 223] → C 类

② C 类网络号 24 位 → 网络号是 222.1.1，主机号是最后一段

③ 两台主机的网络号都是 222.1.1 → 同一网络

结论

✅ 同属 C 类，同一网络 222.1.1.0，可直接通信。

Case 02

案例 2 · 同一 B 类网段

题目

136.0.20.5 与 136.0.30.11　同一网络？属于哪一类？

分析

① 首字节 136 ∈ [128, 191] → B 类

② B 类网络号 16 位 → 网络号是前两段 136.0

③ 两台主机的网络号都是 136.0 → 同一网络

结论

✅ 同属 B 类，同一网络 136.0.0.0，无需路由器转发。

Case 03

案例 3 · 跨类比较

题目

128.36.199.3 与 21.12.240.17　分别属于哪一类？同一网络吗？

分析

① 128.36.199.3：首字节 128 → B 类，网络号 128.36

② 21.12.240.17：首字节 21 → A 类，网络号 21

③ 网络号完全不同 → 不同网络

结论

⚠️ 必须通过路由器才能通信——A 与 B 之间没有共同前缀。

Case 04

案例 4 · 合法性检查

题目

183.194.330.253　合法吗？为什么？

分析

① 第三段是 330——超出 0–255 范围

② 每段最大只能是 255（8 位二进制全 1）

③ 183.194.330.253 不合法——典型的"输入错误"

结论

❌ 非法 IP——配置时一定要校验每段 ≤ 255。

Recap

本章小结

  1. IP 地址屏蔽物理地址差异，标识网络接口
  2. 32 位二进制 → 点分十进制（4 段 0–255）
  3. netid + hostid 两层结构，路由器按 netid 转发
  4. A / B / C / D / E 五类，netid 长度 8 / 16 / 24 位
  5. 特殊 IP：网络地址、广播地址、回送 127.0.0.0/8、私有 10/8 · 172.16/12 · 192.168/16
