背景 · RIP 概述

RIP（Routing Information Protocol）：基于「向量-距离」算法。

- 度量：跳数（hop count），最大 15 跳（16 = 不可达） - 更新周期：每 30 秒广播 / 组播一次完整路由表 - 版本：RIPv1（有类、广播）、RIPv2（无类、组播 224.0.0.9、支持 VLSM） - 管理距离：120

BG · 02

背景 · RIP 关键命令

RIP 配置常用命令汇总：

STEP 01

搭建拓扑

  • PT 6.2 新建 Lab4-RIP.pkt。
  • 拖设备、连线（同 Lab 3）。
  • 不要配置静态路由——本实验目的是让 RIP 自动学习。
  • Serial DCE 端配 clock rate 64000。
STEP 02

路由器基本配置 + 接口 IP

  • 每台路由器同 Lab 3 配置 hostname、密码、接口 IP（按地址规划表）。
  • Serial DCE 端记得 clock rate 64000。
  • PC IP 与网关也按 Lab 3 配置。
STEP 03

启动 RIP 并宣告网络（R1）

  • 在 R1 CLI 输入以下命令：
  • enable → configure terminal
  • router rip — 启动 RIP 进程
  • version 2 — 切换到 RIPv2
  • no auto-summary — 关闭自动汇总
  • network 192.168.1.0 — 宣告 LAN1（主类网）
  • network 10.0.0.0 — 宣告串口链路（10.x 都属于 10.0.0.0/8）
  • passive-interface FastEthernet0/0 — LAN 口不发 RIP 更新
  • end → write memory
STEP 04

R2 的 RIP 配置

  • 启动 RIP 进程：router rip。
  • version 2、no auto-summary。
  • 宣告：network 10.0.0.0、network 192.168.2.0。
  • passive-interface FastEthernet0/0。
  • end; write memory。
STEP 05

R3 的 RIP 配置

  • router rip → version 2 → no auto-summary。
  • 宣告：network 192.168.3.0、network 10.0.0.0。
  • passive-interface FastEthernet0/0。
  • end; write memory。
TIP

network 10.0.0.0 是关键——R1/R2/R3 的 Serial 链路（10.1.0.0/24 + 10.2.0.0/24）都属于主类 10.0.0.0/8，所以一条 network 命令就宣告了两段串行链路。

STEP 06

观察 RIP 自动学习

  • 等约 30 秒，让 RIP 完成第一次完整更新。
  • 在 R1 上 show ip protocols：可看到 RIP 进程信息、宣告的网络、被动接口、计时器。
  • 在 R1 上 show ip route：应能看到 R 192.168.2.0/24 [120/1] via 10.1.0.2 与 R 192.168.3.0/24 [120/2] via 10.1.0.2 与 R 10.2.0.0/24 [120/1] via 10.1.0.2。
  • 等 30 秒后再看一次——RIP 每 30 秒交换路由表。
STEP 07

测试连通性

  • PC1 ping PC2：通
  • PC1 ping PC3：通
  • PC2 ping PC3：通
  • 注意 TTL：跨 1 跳 → 127；跨 2 跳 → 126。
STEP 08

抓包观察 RIP 报文

  • 切到 Simulation 模式。
  • 让 PC1 ping 一次 PC1 网关或触发 RIP 更新（也可在 R1 上 debug ip rip）。
  • 观察过滤器中 RIP 报文：RIPv2 用组播 224.0.0.9 发送更新（不是广播）。
  • 每 30 秒看到一次。
STEP 09

观察 RIP 的慢收敛与防环

  • 把 R1 的 S0/0/0 串口 shutdown（模拟链路断开）。
  • 等 180 秒（6 个 RIP 周期），观察 R1 的路由表：
  • 192.168.2.0 与 192.168.3.0 的 RIP 条目消失（超时）。
  • 把 R1 的 S0/0/0 no shutdown 恢复。
  • 再等约 30 秒，路由表恢复——RIP 慢收敛的典型现象。
STEP 10

进阶 · debug ip rip

  • 在 R2 的 CLI：enable → debug ip rip。
  • 观察实时 RIP 收发更新——会看到大量 RIP: Received packet from ... 信息。
  • 关闭调试：no debug all 或 undebug all。
STEP 11

进阶 · RIPv1 与 RIPv2 兼容

  • 把 R1 的版本改回 version 1。
  • 等 30 秒，观察 R2 收到的路由——RIPv1 不携带子网掩码，会按主类（10.0.0.0/8）汇总。
  • 再把 R1 改回 version 2，恢复正常。

ERR · 01

常见错误与排错

路由表没有 R 条目

network 未宣告 / Serial 未 up → show ip protocols 检查。

邻居路由不通

network 漏配 / 掩码不一致 → 检查所有 router 的 network。

实验 7 中 PC1 仍能 ping PC2（应不通）

RIP 没真超时 → 等满 180 秒或 clear ip route *。

RIPv1 把路由按主类汇总

未关闭 auto-summary → no auto-summary + version 2。
