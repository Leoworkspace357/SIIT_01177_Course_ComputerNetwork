PART 01

为什么需要协议？

从一封信的例子看「通信」的复杂性。

Motivation · A

一个生活中的通信例子

A

任务

教师 A 写一封通知书，发给远在北京的同学 B——这本身就是一次通信。

B

环节

A 用中文写好信 → 交给教务秘书 → 投进邮筒 → 邮局选择路线 → 打包 → 火车站运输 → 到达北京……

?

问题

到达北京之后，B 怎么收到？每一步又该遵守什么规则？

Analysis · 01

例子背后的几个观察

  • 目的：通信——把信息从 A 传到 B
  • 每个人都遵守一定的规则（写信用中文、地址格式、邮戳……）
  • A 按一定的格式写好信
  • 秘书在信封上填好地址
  • 邮局选择路线、按邮件处理方法发送
  • 铁路有自己的运作方式——它不需要知道信的内容
  • 每个人协同工作、相互依赖，但又相互独立

Analysis · 02

分工与分层

  • 每个人又相互独立——只关心上一层做了什么
  • 明确分工：秘书只需把信投到邮筒；邮递员不需会开火车
  • 上一层只关心「下一层做了什么」，不关心「怎么做」
  • 这种分工，就是分层的思想
  • 层与层之间通过接口沟通——「把信投进邮筒」就是一层接口

Why It Matters

计算机通信完全一样

相同点

多角色协作

发送方 / 接收方 / 交换机 / 路由器 / 运营商 / 应用程序……每个角色都有自己的规则。

不同点

电信号替代马车

介质从「铁路」变成「光纤、铜线、无线电磁波」，但「按规则合作」的本质不变。

结论

必须协议化

没有事先约定好的规则，异构的设备根本无法相互理解。

方法

用分层管理复杂

把通信这件事切成若干层，每层只关心自己的事——这是软件工程里最经典的方法之一。

PART 02

协议 · Protocol

一组约束通信行为的规则——语法、语义、时序。

Definition

什么是计算机通信协议？

目的

完成通信

让分布在不同地点的设备能够交换有意义的信息。

定义

一组规则

为计算机能通信而制定的规则集合，约束格式、时序与含义。

作用

协同工作

规定不同设备应如何协同，以保证数据准确到达对方。

Three Elements

协议三要素

语法

Syntax

数据结构与格式——字段如何排列，传输以何种二进制形式表示。

语义

Semantics

每个字段的含义——收到后做什么动作，如何响应。

时序

Timing

事件发生的先后与速率匹配——何时发、何时收、超时怎么办。

Examples

常见的网络协议

  • TCP/IP　互联网的事实标准
  • IPX/SPX　Novell NetWare 时代的协议
  • NetBEUI　早期 Windows 局域网协议
  • AppleTalk　苹果设备使用的协议族
  • HTTP / FTP / DNS / DHCP　应用层的常见协议
  • ……理论上你也可以制定一个自己的协议（只要双方都遵守）

PART 03

OSI 体系结构

由 ISO（国际标准化组织）提出的七层参考模型。

Background

OSI 模型的由来

  • 1970s：各大厂商各自为政，IBM 有 SNA、DEC 有 DECnet、Novell 有 IPX……
  • 网络互联举步维艰——不同厂家的设备互不兼容
  • 1977 年 ISO（国际标准化组织）开始制定开放系统互连参考模型
  • 1984 年正式发布 OSI/RM（Open Systems Interconnection Reference Model）
  • 目标：让任何厂商的设备只要遵守 OSI，都能相互通信
  • 虽然 OSI 实际没有被完全实现，但它是教学与理论分析的基石

OSI · 7 Layers

OSI 七层模型

  • 应用层　为用户提供网络服务接口
  • 表示层　数据格式、编码、加密、压缩
  • 会话层　建立、维护、管理会话
  • 传输层　端到端的可靠 / 不可靠传输
  • 网络层　寻址与路由选择
  • 数据链路层　介质访问、差错检测
  • 物理层　比特流的电/光/机械传输

Visual · Stack

七层模型的「纵向」视角

L7应用层Application
L6表示层Presentation
L5会话层Session
L4传输层Transport
L3网络层Network
L2数据链路层Data Link
L1物理层Physical

记忆口诀　应表会传网链物（从上到下）　·　物链网传会表应（从下到上）

Why Layers

为什么要分层？

  • 分层是解决复杂问题的好方法
  • 分层意味着分工：每一层只关心自己的事
  • 各层之间独立——一层变化不影响其他层
  • 易于实现与维护
  • 有利标准化：不同厂家的设备可以共存
  • 每层只看到「下一层提供的服务」，不必关心「如何实现」
  • 这与软件开发中模块化、接口抽象的思想完全一致

Key Concepts

服务、接口、协议

Service

服务

某一层向上一层提供的功能。「我能为你做什么」。

Interface

接口

相邻层之间交互的规则，定义「怎么调用」。

Protocol

协议

同一层之间通信的规则，对等实体间的「对话」。

例：IP 协议定义同层的包格式（Protocol）；IP 与 TCP 的接口是「把数据交给 IP」；IP 向 TCP 提供的服务是「尽力而为的分组转发」。

PART 04

TCP/IP 体系结构

互联网真正在用的四层模型——先有实践，后有标准。

Background

TCP/IP 模型的诞生

  • 1969 年 ARPANET 启动，先有网络后有标准
  • 1974 年 Cerf 与 Kahn 发表 TCP/IP 协议论文
  • 1983 年 ARPANET 全面切换到 TCP/IP——「互联网生日」
  • 它比 OSI 更早成熟，更贴合实际工程
  • 今天整个互联网都跑在 TCP/IP 上
  • OSI 偏理论，TCP/IP 偏实践——但二者相辅相成

TCP/IP · 4 Layers

TCP/IP 四层模型

  • 应用层　HTTP、FTP、SMTP、DNS、DHCP……
  • 传输层　TCP（可靠）、UDP（不可靠）
  • 网际层　IP、ICMP、ARP、IGMP
  • 网络接口层　以太网、Wi-Fi、PPP、光纤……

Visual · Stack

TCP/IP 四层「纵向」视角

L4应用层Application
L3传输层Transport
L2网际层Internet
L1网络接口层Link / Network Access

Mapping

OSI vs TCP/IP · 对应关系

OSI 层TCP/IP 层典型协议 / 设备
应用层应用层HTTP、FTP、SMTP、DNS、DHCP
表示层数据格式、加密、压缩
会话层Sockets、RPC
传输层传输层TCP、UDP
网络层网际层IP、ICMP、ARP
数据链路层网络接口层以太网、Wi-Fi、PPP
物理层网卡、光纤、电缆

Compare

OSI 与 TCP/IP 的核心差异

OSI

理论驱动

先有模型，后有协议；分层细致（7 层），通用性强；实现复杂，市场未广泛采纳。

TCP/IP

实践驱动

先有协议，后有模型；分层简洁（4 层），工程性强；互联网事实标准。

学习建议　用 OSI 理解概念，用 TCP/IP 理解实际工程。两者不冲突，而是互补。

Five-Layer

五层教学模型（折中）

L5应用层Application
L4传输层Transport
L3网络层Network
L2数据链路层Data Link
L1物理层Physical

中国教材最常用——把 TCP/IP 的网络接口层拆成数据链路层 + 物理层，便于讲清细节。

PART 05

OSI 各层详解

从最底层的「0 和 1」一路走到应用层。

Layer 01 · Physical

物理层 · 比特流的传输

比喻：信是用火车拉还是汽车拉？——介质与方式
  • 负责 0 和 1 的传送——透明的比特流
  • 使用什么传输介质？（双绞线、光纤、无线电波……）
  • 0 和 1 在线路上如何表示？（电压、光脉冲、调制方式）
  • 线的接头是什么样的？机械尺寸、引脚定义
  • 比特率（bps）、带宽（Hz）、编码方式（NRZ、曼彻斯特）

Layer 01 · Specs

物理层关心的 4 类特性

机械

Mechanical

接口形状、尺寸、引脚数与排列——「什么形状的插头」。

电气

Electrical

电压范围、阻抗、传输速率——「线上跑多高的电平」。

功能

Functional

每根线的作用：数据、时钟、地——「每根线是干嘛的」。

规程

Procedural

比特传输的先后顺序、握手流程——「怎么把 0/1 摆上线路」。

Layer 02 · Data Link

数据链路层 · 帧与差错

比喻：邮局在信封上盖邮戳——给比特流分组
  • 帧的封装：将传输数据增加同步信息、校验信息与地址信息后封装成帧
  • 差错检测：检错但不纠错；常用循环冗余校验（CRC）
  • 介质访问控制（MAC）：同一线路上多台计算机要访问时避免冲突
  • 典型协议：以太网（Ethernet）、Wi-Fi（802.11）、PPP、HDLC
  • 典型设备：交换机（Switch）、网卡（NIC）

Layer 02 · Sublayers

数据链路层的两个子层

LLC

逻辑链路控制

Logical Link Control——向上层提供统一的接口；负责「与上层对接」。

MAC

介质访问控制

Media Access Control——向物理层，管理对共享介质的访问；MAC 地址 就在这一层。

Layer 03 · Network

网络层 · 寻址与路由

比喻：信从什么线路送到北京？——确定走哪条路
  • 定址：数据是谁发的、发给谁？用IP 地址标识网络中的主机
  • 路由选择：从源到目的选择最佳路径
  • 跨越多个网络的转发与拥塞控制
  • 把分组（packet）从一跳送到下一跳——逐跳转发
  • 典型协议：IP、ICMP、ARP、OSPF、BGP
  • 典型设备：路由器（Router）

Layer 03 · Key

IP · 网络层的核心

IPv4

32 位地址

约 43 亿个地址，已基本耗尽；点分十进制表示，如 192.168.1.1。

IPv6

128 位地址

约 3.4×10³⁸ 个地址；冒号十六进制表示，如 2001:da8::1。

Best-effort

尽力而为

IP 不保证可靠、不保证顺序——只管尽力送，「不签合同」。

Hop-by-hop

逐跳转发

每个路由器独立决定下一跳；「只管把包交给下一站」。

Layer 04 · Transport

传输层 · 端到端

比喻：秘书发现对方没收到信，会再发一封——可靠性与端口
  • 提供可靠（或不可靠）的端到端服务
  • 流量控制：避免发送方压垮接收方
  • 差错控制与重传机制（TCP）
  • 端口号 区分同一主机上的不同应用（80、443、22……）
  • 典型协议：TCP（面向连接、可靠）、UDP（无连接、快速）
  • 把网络层「尽力而为」的服务补全为可靠的端到端——这是传输层的关键

Layer 04 · TCP vs UDP

TCP vs UDP

TCP

面向连接 · 可靠

三次握手建立连接；四次挥手关闭；重传、排序、流控、拥塞控制。例：HTTP、FTP、SMTP。

UDP

无连接 · 快速

发完就走，不保证到达、不保证顺序；开销小、延迟低。例：DNS、直播、视频会议。

Layer 05 · Session

会话层 · 管理对话

比喻：元首之间的会晤——先派人谈好议事规则
  • 允许用户在设备之间建立、维持、终止会话
  • 会话管理：检查点、恢复、同步
  • 在数据流中插入同步点，断线后能从断点恢复
  • 举例：在线编辑文档时，自动保存检查点；网络中断后可恢复
  • OSI 实际中很少独立实现——功能常被并入应用层
  • 典型协议：RPC、NetBIOS、PPTP

Layer 06 · Presentation

表示层 · 数据表示

比喻：信用中文还是英文写？——双方得能互相看懂
  • 对数据进行编码——「让对方能解码」
  • 数据压缩：减少传输量
  • 数据加密 / 解密：保证机密性
  • 处理数据格式，使不同系统之间能够互相理解
  • 典型标准：ASCII、UTF-8、JPEG、MPEG、SSL/TLS
  • OSI 中独立成层，TCP/IP 中并入应用层

Layer 07 · Application

应用层 · 实际的协议

  • HTTP / HTTPS　网页浏览
  • FTP / SFTP　文件传输
  • SMTP / POP3 / IMAP　邮件
  • DNS　域名解析
  • DHCP　自动分配 IP
  • SSH / Telnet　远程登录
  • 作为用户应用程序与网络之间的接口

Summary · 7 Layers

OSI 各层主要功能

层名称主要功能
7应用层提供应用程序间通信
6表示层处理数据格式、加密、压缩
5会话层建立、维护、管理会话

记忆口诀　应表会传网链物（从上到下）；数据传输时物链网传会表应（从下到上）。

PART 06

封装 · 解封装 · PDU

数据如何在各层之间「加头」与「剥头」。

PDU

PDU · 协议数据单元

Definition

什么是 PDU

Protocol Data Unit——每一层传输数据的基本单位。每层都在上一层 PDU 上加自己的头部，形成新的 PDU。

Names

不同层的 PDU

数据 / 段 / 包 / 帧 / 比特——名字不同，本质都是「加了头的上层数据」。

PDU · Names

每层 PDU 的名称

应用层数据 / DataHTTP, FTP
传输层段 / SegmentTCP, UDP
网络层包 / Packet (Datagram)IP, ICMP
数据链路层帧 / FrameEthernet, Wi-Fi
物理层比特 / Bits电平/光脉冲

Encapsulation

数据封装 · 发送方

从应用层到物理层：每层只关心「自己这一层的协议头」，对上层透明。
L7 · 应用│ HTTP 请求 │Data
L4 · 传输│ TCP 头 │ HTTP 请求 │Segment
L3 · 网络│ IP 头 │ TCP 头 │ HTTP 请求 │Packet
L2 · 链路│ 帧头 │ IP 头 │ TCP 头 │ HTTP │ │ 帧尾 │Frame
L1 · 物理‖‖‖‖‖ 比特流 ‖‖‖‖‖Bits

Decapsulation

数据解封装 · 接收方

从物理层到应用层：每一层剥掉自己的头，把数据交给上层。
  • 物理层收到比特流，交给数据链路层
  • 数据链路层剥掉帧头帧尾，根据 CRC校验，交给网络层
  • 网络层剥掉 IP 头，查路由表决定下一跳，交给传输层
  • 传输层剥掉 TCP/UDP 头，重组数据，交给应用层
  • 应用层拿到原始数据，交给应用程序
  • 这个「加头—传输—去头」过程就是封装 / 解封装

Analogy

用寄信再理解一次

发送

层层包装

信 → 装进信封（加地址） → 装进邮袋（加邮戳） → 装上火车（加车次）。每加一层包装，都为了让下一环节能处理。

接收

层层拆封

火车 → 拆邮袋 → 拆信封 → 拿到信。每一环节只管自己的事：邮局只管邮袋，铁路只管火车。

PART 07

对比 · 总结 · 拓展

学完本章之后的总览。

Why TCP/IP Won

为什么是 TCP/IP 赢了？

  • OSI 设计过度：层次太多、实现复杂、运行效率低
  • TCP/IP 简单实用：4 层足够，开源、免费、文档完整
  • 美国国防部 ARPANET 强力背书，并入 BSD Unix
  • 市场先入为主——先有生态，后有标准
  • OSI 没有真正完整的实现，最终沦为教学模型
  • 今天5G、IoT、云……都跑在 TCP/IP 之上

Layered Thinking

分层的思维方式

分解

复杂问题

把大而复杂的问题切小，每层只关心自己的事。

抽象

隐藏细节

上层看不见下层实现，「知道有这回事就行」。

复用

独立演进

一层变化不影响其他层——TCP 改了协议，IP 不用动。

这正是计算机科学最核心的思维方式——分层 = 抽象 = 复用。

Misconceptions

常见误解 · 别踩坑

  • 「OSI 已经被淘汰了」——不。OSI 是教学与理论分析的标准，仍在广泛使用。
  • 「TCP 比 UDP 好」——错。两者适用场景不同：视频会议用 UDP，文件传输用 TCP。
  • 「IP 一定要用 TCP」——错。IP 之上可以是 TCP，也可以是 UDP，甚至 ICMP、IGMP。
  • 「应用层就是应用程序」——不。应用层是协议（HTTP、SMTP），应用程序使用这些协议。
  • 「MAC 地址就是 IP 地址」——错。MAC 在链路层，IP 在网络层，作用不同。

04

思考题

为什么说「分层 = 抽象 = 复用」？试举出 3 个生活中分层思想的例子。

Layer 01 · Devices

物理层典型设备与介质

介质

有线

双绞线、同轴电缆、光纤——RJ-45、SC、LC 等接口。

介质

无线

无线电波、微波、红外——Wi-Fi、4G/5G、卫星。

设备

中继器 / 集线器

中继器放大信号；集线器（Hub）把多台设备连到同一物理介质。

Layer 02 · Frame

一个真实的以太网帧

前导码‖ 7 字节 10101010… + 1 字节 SFD ‖同步
MAC 头‖ 6B 目的 MAC │ 6B 源 MAC │ 2B 类型 ‖寻址
载荷‖ 46–1500 字节 数据 ‖上层 PDU
FCS‖ 4 字节 CRC 校验 ‖检错

交换机读取目的 MAC决定转发端口；FCS 校验失败则丢弃该帧。

Layer 03 · Routing

路由器如何决定下一跳？

查表

路由表

每台路由器维护一张路由表：目的网络 → 下一跳 / 出接口。

匹配

最长前缀匹配

拿目的 IP与路由表逐条比较，选前缀最长的那条——更具体者优先。

学习

动态 vs 静态

静态路由由管理员手写；动态路由由 OSPF、RIP、BGP 等协议自动学习。

决策

默认网关

表里没有匹配的条目时，丢给默认网关——「不知道就转给上级」。

Layer 04 · TCP

TCP 三次握手

Client

SYN

seq = x
→
Server

SYN + ACK

seq = y, ack = x+1
→
Client

ACK

ack = y+1
  • 第一次：客户端发 SYN，请求建立连接
  • 第二次：服务器回 SYN + ACK，同意并同步自己的序号
  • 第三次：客户端发 ACK 确认，连接建立
  • 为什么是三次？——「双方各确认一次收、发能力」

L5–L7 · Detail

高层三层的「分工」

会话层 L5

谁在「对话」

管对话——会话建立、维持、同步、终止；插入检查点以便断线恢复。

表示层 L6

「说」的是什么

管数据形式——编码、解码、加密、压缩；让不同系统能互相读懂。

应用层 L7

用户「做什么」

管业务——HTTP、FTP、SMTP……直接面对用户的需求。

Compare · Deep

OSI 与 TCP/IP · 详细对比

维度OSITCP/IP
层数7 层4 层
诞生顺序先有模型，后有协议先有协议，后有模型

网络接口拆成链路层+物理层合为一层

History

OSI 失败的几个原因

  • 专家闭门造车——理论与工程脱节
  • 协议实现复杂，开发周期长
  • 政府和 ISO 推动，缺乏商业生态
  • TCP/IP 已被 Unix 集成，免费、开源、好用
  • 「Worse is Better」——简单方案常常赢过完美方案
  • 结果：OSI 成了教学模型，TCP/IP 成了实际网络

In Practice

分层思维在排错中的应用

自下而上

物理 → 应用

先查物理层（网线、Wi-Fi）→ 链路层（MAC、交换机）→ 网络层（IP、路由）→ 传输层（端口、TCP）→ 应用层（HTTP、DNS）。

工具

每层都有命令

ping（网络层）、traceroute（路由）、netstat（传输层）、curl（应用层）——分层定位问题。

Standards

谁在制定协议标准？

ISO

国际标准化组织

提出 OSI 参考模型；www.iso.org。

IETF

互联网工程任务组

以 RFC 形式发布互联网标准——TCP、IP、HTTP、BGP 等。

IEEE

电气电子工程师学会

802 系列（以太网、Wi-Fi）——链路层与物理层标准。

ITU-T

国际电信联盟

电信领域标准；X.25、ATM、H.323 等。

IANA / ICANN

号码资源分配

管理 IP、域名、端口号等全球唯一资源。

W3C

万维网联盟

HTML、CSS、Web 协议等应用层标准。

Future

分层模型在今天还够用吗？

仍然够用

基础没变

5G、Wi-Fi 6、云计算、SDN……底层仍是 IP。分层模型是思考工具，不会过时。

新挑战

跨层优化

实时音视频、IoT 协议出现跨层设计——为了性能打破严格的分层边界。

分层是思想，不是教条；理解了为什么分层，就能在何时该跨层上做出正确判断。
