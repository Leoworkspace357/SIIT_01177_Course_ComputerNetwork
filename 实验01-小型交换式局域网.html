PART 01

实验目的

  1. 熟悉 Cisco Packet Tracer 6.2 的界面与基本操作（设备选择、连线、配置）。
  2. 掌握主机名、IP 地址、子网掩码、默认网关的基本配置方法。
  3. 学会使用 ping、ipconfig 验证网络连通性。
  4. 理解共享式 LAN（HUB） 与 交换式 LAN（Switch） 的区别。
  5. 培养观察指示灯、阅读命令输出的排错能力。

实验拓扑

BG · 01

背景 · Packet Tracer 6.2 界面

打开 PT 6.2 后，左下角 Network Devices 与 End Devices 是设备库。

单击设备 → 在工作区拖出；按住 Ctrl 多选批量放置。

用 Connections 选择线缆类型（最常用 Copper Straight-Through 与 Copper Cross-Over）。

单击设备 → 弹出配置窗口，有 Physical / Config / CLI / Desktop 四个标签。

STEP 01.1

设备端口速查

不同设备的默认端口与状态不同，配置前确认清楚。

设备常用端口默认状态
PC-PTFastEthernet0已启用
Hub-PTPort0 ~ PortN即插即用
Switch 2960-24TTFastEthernet0/1 ~ 0/24默认 VLAN1
STEP 01.2

新建拓扑文件

  • 启动 Packet Tracer 6.2 → File → New。
  • File → Save As… → 文件名 Lab1-SmallLAN.pkt → 保存到本地。
  • 在右下角 End Devices 中选 PC → 拖出 4 台。
  • 在 Network Devices 中选 Hub → 拖出 1 台；选 Switches → 2960-24TT → 拖出 1 台。
STEP 01.3

连线（按拓扑图）

  • 选择 Connections → Copper Straight-Through。
  • 单击 PC0 → 选 FastEthernet0，再单击 Hub0 → 选 Port0。
  • 同样连接 PC1-Hub0(Port1)、PC2-Hub0(Port2)。
  • 选择一根线把 Hub0 的某端口接到 Switch0 的 Fa0/1（HUB ↔ SWITCH 异种设备 → 直连线）。
  • 再用一根直连线连接 PC3 的 Fa0 到 Switch0 的 Fa0/2。
TIP

HUB ↔ SWITCH 是异种设备 → 用直连线；同种设备（如 SWITCH-SWITCH 早期）才用交叉线。本实验所有连线都是直连线。

STEP 01.4

配置 PC 的 IP 地址

每台 PC 设为静态 IP。单击 PC → Desktop → IP Configuration → Static → 填写。

PCIP 地址子网掩码
PC0192.168.10.10255.255.255.0
PC1192.168.10.11255.255.255.0
PC2192.168.10.12255.255.255.0
PC3192.168.10.20255.255.255.0
TIP

也可以在 Config 标签的 FastEthernet0 接口里直接填写 IP，效果一样。

STEP 01.5

观察指示灯

  • 仔细观察设备上的小圆点（指示灯）。
  • HUB 端口：插线后立即变绿；数据传输时闪烁。
  • Switch 端口：绿 = up，灭 = down；PC3 的端口指示灯应为绿色。
  • 如果某个端口指示灯不亮 → 检查物理连线是否牢固。
STEP 01.6

测试连通性（ping）

  • 单击 PC0 → Desktop → Command Prompt。
  • 在命令提示符输入 ping 192.168.10.11 — 看到「Reply from 192.168.10.11 ...」表示 PC0 ↔ PC1 通。
  • 同样测试 PC0 → PC2、PC0 → PC3：都应通。
  • 测试 PC1 → PC3：应通。
  • 测试 PC0 → 192.168.10.99（不存在的 IP）：应显示「Request timed out」。
STEP 01.7

观察 HUB 与 SWITCH 的差异（Simulation 模式）

  • 进入 Simulation 模式（右下角切换）。
  • 让 PC0 ping PC1，并单步跟踪数据包。
  • HUB 会把 PC0 的帧广播给 Port0、Port1、Port2（PC0、PC1、PC2 都收到），然后只有 PC1 应答；PC2 也会收到 PC0 的包但丢弃。
  • Switch 收到 PC0 的帧后，先学习 PC0 的 MAC，记录到 MAC 表；接着查 MAC 表看 PC1 在哪个端口 → 直接转发给 PC3 那条链路上的端口（不广播）。
  • 切回 Realtime 模式继续。
STEP 01.8

交换机 CLI 基本查看

单击 Switch0 → CLI 标签。等出现提示符 Switch> 后输入以下命令，观察输出。

Switch> "kw">enable Switch# "kw">show "kw">version Switch# "kw">show mac-address-table Switch# "kw">show interfaces status Switch# "kw">exit

ERR · 01

常见错误与排错

ping 不通（Request timed out）

可能原因：IP 错 / 子网掩码错 / 网线松。处理：重新检查 IP 配置与指示灯。

ping 不通（Destination unreachable）

可能原因：默认网关未配且跨网段（本实验内无路由器，可忽略）。

Switch 端口指示灯不亮

可能原因：线缆物理故障 / 端口损坏。处理：换线或换端口。

Simulation 中 HUB 也显示单播转发

视图问题。切到 Hub 中间观察「广播」效果。

思考题

思考题

  1. 同一网段内 IP 不同、子网掩码相同，能 ping 通吗？为什么？
  2. 为什么 HUB 会引起「冲突域」问题，而 Switch 不会？
  3. 在只有 Switch 的网络中，A 给从未通信过的 B 发包，Switch 会怎么处理？
  4. 如果把 PC0 的子网掩码错填为 255.255.0.0，其他 PC 不变，会发生什么现象？
