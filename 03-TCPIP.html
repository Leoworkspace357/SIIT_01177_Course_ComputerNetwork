PART 01

TCP/IP 概述

互联网事实标准的协议族。

Definition

什么是 TCP/IP？

字面

两个核心协议

TCP（传输控制协议）+ IP（网际协议），但实际涵盖整个协议族。

本质

协议族

一组协议的总和——TCP、IP、UDP、HTTP、FTP、DNS、ARP……

地位

Internet 的基石

整个互联网都跑在 TCP/IP 之上——没有它，就没有今天的网络世界。

来源

ARPA → 全球

从美国国防部 ARPANET 项目起步，如今是全球统一的通信语言。

Features

TCP/IP 的核心特点

  • 开放的协议标准　免费、公开，可独立于特定硬件与操作系统
  • 跨网络运行　可运行于局域网、城域网、广域网，覆盖范围最广
  • 统一的地址方案　所有设备都使用IP 地址进行寻址
  • 层次化结构　每层独立演进，便于开发和维护
  • 事实标准　不是由 ISO 强制，而是被业界广泛采用形成的事实标准
  • 端到端确认　不依赖单一链路，「自愈能力强」

History

TCP/IP 的诞生

1969
ARPANET

美国国防部组建 ARPANET，4 台节点互联。

1974
TCP/IP 论文

Cerf & Kahn 发表 TCP/IP 协议设计论文。

1983
全面切换

ARPANET 切到 TCP/IP——互联网生日。

1990s+
全球扩张

WWW 出现，互联网爆发式增长。

4 Layers

TCP/IP 四层模型

L4 · 应用

应用层

HTTP、FTP、SMTP、DNS、DHCP……所有高层协议都在这一层。

L3 · 传输

传输层

TCP（可靠）与 UDP（不可靠），提供端到端通信。

L2 · 网际

网际层

IP、ICMP、ARP、IGMP——负责把分组从源送到目的。

L1 · 接口

网络接口层

以太网、Wi-Fi、PPP——物理传输与帧的封装。

Visual · Stack

TCP/IP 模型的纵向视角

L4应用层Application
L3传输层Transport
L2网际层Internet
L1网络接口层Link / Access

常见记忆：应传网接　·　数据传输方向：应用 → 传输 → 网际 → 接口

OSI ↔ TCP/IP

TCP/IP 与 OSI 的对应

OSI 层TCP/IP 层对应协议示例
应用层 / 表示层 / 会话层应用层HTTP、FTP、SMTP、DNS
传输层传输层TCP、UDP
网络层网际层IP、ICMP、ARP
数据链路层 / 物理层网络接口层Ethernet、PPP、Wi-Fi

TCP/IP 把 OSI 的上三层合并，下两层也合并——这就是它「更实用、更易实现」的根源。

PART 02

应用层协议

用户看得见摸得着的「网络服务」。

App · Overview

常见应用层协议

Web

HTTP / HTTPS

超文本传输；HTTPS = HTTP + TLS 加密。端口 80 / 443。

Transfer

FTP / SFTP

文件传输协议；SFTP 通过 SSH 加密。端口 20/21 / 22。

Mail

SMTP / POP3 / IMAP

邮件发送 / 接收协议。端口 25 / 110 / 143。

Name

DNS

域名 → IP 地址解析。端口 53（UDP / TCP）。

Config

DHCP

自动分配 IP、子网掩码、网关。端口 67/68。

Remote

SSH / Telnet

远程登录；SSH 加密，Telnet 明文。端口 22 / 23。

HTTP

HTTP · Web 的语言

  • 请求 / 响应 模型：客户端发请求，服务器回响应
  • 典型方法：GET（取）、POST（提交）、PUT、DELETE
  • 状态码：200 成功、404 未找到、500 服务器错误
  • HTTPS = HTTP + TLS——在 HTTP 与 TCP 之间插入加密层
  • 一次 HTTP 请求的完整旅程：浏览器 → DNS → TCP → HTTP → 渲染

DNS

DNS · 互联网的「地址簿」

作用

域名 → IP

www.baidu.com → 220.181.38.148——把人类易记的名字翻译成机器用的地址。

层次

分布式数据库

根 → 顶级域 → 二级域 → 主机——全球 13 组根服务器，分级查询。

查询

递归 / 迭代

客户端递归查询，本地 DNS 迭代查询根、顶级、权威服务器。

优化

缓存

各级 DNS 服务器缓存结果，加快后续查询，减小根服务器压力。

DHCP

DHCP · 自动分配地址

没有 DHCP，每台新设备都要手动配置 IP、子网掩码、网关、DNS——繁琐且易错。
  • DORA 四步：Discover → Offer → Request → ACK
  • 客户端广播「谁给我一个 IP？」
  • 服务器从地址池选一个，下发给客户端
  • 客户端租约期内使用，到期可续租
  • 家庭路由器、企业网络、校园网都跑着 DHCP

PART 03

传输层：TCP 与 UDP

为应用程序提供端到端的通信服务。

Transport · Role

传输层的角色

  • 为应用进程提供端到端的逻辑通信
  • 在 IP 「尽力而为」的基础上，补偿可靠性（TCP）或保持高效（UDP）
  • 通过端口号区分同一主机上的不同应用
  • 典型端口：HTTP 80 / HTTPS 443 / SSH 22 / DNS 53
  • 是程序员编写网络程序时直接打交道的层——socket API

TCP vs UDP

TCP 与 UDP 的对比

TCP

面向连接 · 可靠

三次握手建立连接；四次挥手关闭；重传、排序、流控、拥塞控制。

UDP

无连接 · 快速

发完就走；不保证到达、顺序；开销小、延迟低。

特性TCPUDP
连接面向连接无连接
可靠性可靠（重传、确认）不可靠（尽力而为）
顺序保证顺序不保证
速度慢（开销大）快（开销小）
应用HTTP、FTP、邮件DNS、视频、直播、游戏

TCP · 3WHS

TCP 三次握手

Client

SYN

seq = x
→
Server

SYN + ACK

seq = y, ack = x+1
→
Client

ACK

ack = y+1
  • 第一次：客户端 SYN，请求建立连接
  • 第二次：服务器 SYN + ACK，同意并同步序号
  • 第三次：客户端 ACK，连接建立
  • 为什么是三次？——双方各确认一次「收」和「发」能力

TCP · 4WT

TCP 四次挥手

  • 第一次：客户端 FIN　「我发完了」
  • 第二次：服务器 ACK　「我知道了，但你先等一下」
  • 第三次：服务器 FIN　「我也发完了」
  • 第四次：客户端 ACK　「好的，连接关闭」
  • 等待 2MSL（约 2 分钟）后真正释放——防「迟到包」干扰
  • 为什么是四次？因为 TCP 是全双工——双方都得单独关

Port

端口号 · 应用的「门牌号」

范围

0 – 65535

16 位端口号；0–1023 是知名端口，由 IANA 分配给标准服务。

区分

同一 IP 上的多个应用

一台服务器可以同时跑 HTTP（80）、HTTPS（443）、SSH（22）——靠端口区分。

套接字

Socket = IP + Port

192.168.1.1:80——IP 标识主机，Port 标识进程。

三类

知名 / 注册 / 动态

0–1023 知名；1024–49151 注册；49152–65535 动态（客户端临时）。

PART 04

网际层：IP

整个 TCP/IP 协议族的基石——把分组送到任何地方。

IP · Role

IP 协议 · 网际层的核心

  • 无连接　每个 IP 分组独立转发
  • 不可靠　不保证送达、不保证顺序——尽力而为
  • 点对点　只关心「下一跳」是谁
  • 每台主机必须有唯一 IP 地址
  • 正是 IP 的简单，让互联网能互联全球几十亿设备

IPv4

IPv4 · 32 位地址

格式

点分十进制

4 个 0–255 的十进制数，192.168.1.1，共 2³² ≈ 43 亿个。

结构

网络号 + 主机号

前 N 位是网络号，后 32–N 位是主机号——由子网掩码界定。

分类

A / B / C 类

A 类 0.x.x.x（巨型）、B 类 128.x.x.x（大）、C 类 192.x.x.x（小）。

私有

内网地址

10.x.x.x、172.16–31.x.x、192.168.x.x——不暴露在公网。

IPv6

IPv6 · 128 位地址

  • 地址耗尽的终极解决方案——2¹²⁸ 个，约 3.4×10³⁸
  • 格式：2001:da8:1234:5678::1（冒号十六进制）
  • 比 IPv4 更简洁的 header、内置 IPSec、无广播（用组播代替）
  • 中国2025 年规划：IPv6 活跃用户数达到 8 亿
  • 目前 IPv4 / IPv6 双栈共存（Dual Stack）——过渡期

Subnet Mask

子网掩码 · 网络号与主机号的「分界线」

作用

划分网络

连续 1 表示网络位，连续 0 表示主机位——如 255.255.255.0 = /24。

例

192.168.1.10/24

前 24 位是网络号（192.168.1），后 8 位是主机号（10）。

CIDR

无类域间路由

Classless Inter-Domain Routing——斜杠后数字表示网络前缀长度。

意义

决定广播域

同一子网内主机直接通信；不同子网必须经过路由器。

Routing

路由 · 把分组送到下一跳

  • 每台路由器维护一张路由表：目的网络 → 下一跳 / 出接口
  • 决策原则：最长前缀匹配（more specific wins）
  • 直连路由　接口所在网络自动学习
  • 静态路由　管理员手写（小型网络）
  • 动态路由　OSPF、RIP、BGP 等协议自动学习（大型网络）
  • 没有匹配项？——默认网关，「交给上级」

ARP

ARP · IP 到 MAC 的桥梁

  • 已知对方 IP，但局域网通信需要 MAC——ARP 来翻译
  • 主机广播：「192.168.1.1 是谁？告诉我你的 MAC」
  • 目标主机单播回复：「我是 192.168.1.1，MAC 是 AA:BB:CC:…」
  • 收到的映射被缓存在 ARP 表中（几分钟）
  • 没有 ARP，局域网通信完全无法进行

ICMP

ICMP · 差错与控制

  • Internet Control Message Protocol　IP 协议的辅助协议
  • 用于报告错误：目的不可达、超时、参数错误……
  • ping 命令基于 ICMP Echo Request / Reply
  • traceroute 利用TTL 字段和 ICMP 超时报文，逐跳探测路径
  • ICMP 本身不传数据，只传控制信息

PART 05

网络接口层

最后一公里——把数据变成物理信号。

Link Layer

网络接口层的作用

  • 把 IP 分组封装成帧，加上 MAC 地址等链路信息
  • 在同一物理网络（如以太网、Wi-Fi）上邻居间传送
  • 负责介质访问控制——同一时间谁可以发？
  • 差错检测：CRC 校验，但不纠错——出错就丢
  • 典型技术：以太网（Ethernet）、Wi-Fi、PPP、HDLC

Ethernet

以太网 · 局域网的事实标准

历史

1973 → 10 Gbps

Xerox PARC 发明；从 10 Mbps 到 100M、1G、10G、100G，每 10 年提速 10 倍。

MAC

48 位地址

如 00:1A:2B:3C:4D:5E——前 24 位是厂商代码，后 24 位设备序号。

CSMA/CD

载波监听 / 冲突检测

发送前先听，发送中检测冲突，冲突后退避重试。

Today

全双工 + 交换机

现代以太网都是全双工，通过交换机直连——CSMA/CD 几乎不用了。

Encapsulation

数据在 TCP/IP 中的封装

每加一层头部，就多一层职责——「分工」的真实体现。
应用层

HTTP 请求

GET / HTTP/1.1
Host: www.baidu.com

加 TCP 头

源端口 8888，目的端口 80，seq=1，flags=SYN

网际层 · IP

加 IP 头

源 IP 192.168.1.100，目的 IP 110.242.68.66，TTL=64

接口层 · Ethernet

加帧头帧尾

源 MAC、目的 MAC、EtherType=0x0800、FCS

PART 06

OSI vs TCP/IP · 总结对比

两种参考模型的异同与历史命运。

Common

OSI 与 TCP/IP 的共同点

  • 都采用分层结构，每层向上一层提供服务，向下一层请求服务
  • 都解决异构网络互联问题
  • 都基于协议族的概念——一组协同工作的协议
  • 都强调「下层为上层服务」的单向依赖
  • 都是参考模型，而非具体实现

Differences

OSI 与 TCP/IP 的核心差异

OSI

理论驱动

先有模型，后有协议；7 层细致；通用但复杂，没有真正实现。

TCP/IP

实践驱动

先有协议，后有模型；4 层简洁；实用且高效，成为互联网事实标准。

Why TCP/IP Won

为什么 TCP/IP 胜出？

  • OSI 设计过度——7 层太细、实现复杂、效率低
  • TCP/IP 简单实用——4 层足够，开源、免费、文档完整
  • 美国国防部 ARPANET 强力背书，并入 BSD Unix
  • 先有生态，后有标准——市场规律
  • OSI 沦为教学模型，TCP/IP 成为实际网络
  • 今天5G、IoT、云、SDN——都跑在 TCP/IP 之上

5-Layer

五层教学模型（折中）

L5应用层Application
L4传输层Transport
L3网络层Network
L2数据链路层Data Link
L1物理层Physical

国内教材最常用——把 TCP/IP 的网络接口层拆成数据链路 + 物理，便于讲清细节。

Misconceptions

常见误解 · 别踩坑

  • 「TCP 比 UDP 高级」——错。二者适用场景不同，UDP 在实时场景下更优。
  • 「IP 地址 = 主机身份」——不准确。同一主机可有多 IP；同一 IP 可对应多设备（NAT）。
  • 「DNS 必须用 UDP」——不绝对。大响应、超时重传会切到 TCP。
  • 「MAC 地址全球唯一」——理论上是，但虚拟机、网卡克隆会重复。
  • 「Ping 通 = 网络通」——不。Ping 走 ICMP，可能被防火墙拦；应用层可能仍不通。

此后开始传数据——三次握手本身不携带业务数据。

DNS Walkthrough

DNS 解析的一次完整过程

  1. 浏览器：「www.baidu.com 的 IP？」
  2. 本地缓存查找（命中则直接返回）
  3. 向本地 DNS 服务器发起递归查询
  4. 本地 DNS 向根服务器问：「.com 谁管？」
  5. 根返回 .com 顶级域服务器地址
  6. 再问 .com 服务器：「baidu.com 谁管？」
  7. 返回 baidu.com 权威 DNS 地址
  8. 最后问到 www.baidu.com 的 IP，返回给客户端

NAT

NAT · 内网共享公网 IP

  • IPv4 地址紧张——NAT 让多个内网设备共用一个公网 IP
  • 家用路由器的核心功能——「全家共享一根宽带」
  • NAPT（PAT）最常用：IP + 端口组合标识每个内网连接
  • 优点：节省地址、隐藏内网
  • 缺点：破坏端到端透明性（P2P、VoIP 需要穿透）
  • IPv6 普及后，NAT 终将退出历史舞台

Firewall

防火墙 · 守门人

  • 根据规则决定哪些流量放行、哪些丢弃
  • 工作层次：包过滤（网络层）→ 状态检测（传输层）→ 应用层网关
  • Linux 的 iptables / nftables——经典工具
  • 默认策略：「白名单」优于「黑名单」
  • Ping 不通 ≠ 主机宕机——可能只是ICMP 被拦
  • 现代 NAT + 防火墙往往一体化（家用路由器）

Use Cases

不同场景的协议选择

网页浏览

HTTPS over TCP

可靠性优先——不能丢包；选 TCP；安全再叠 TLS。

视频直播

RTP over UDP

实时优先——丢一帧没关系；选 UDP；容忍延迟但不耐卡顿。

文件下载

HTTP / FTP over TCP

完整性优先——不能丢字节；选 TCP；可重传。

DNS 查询

DNS over UDP (small)

短小、低延迟——选 UDP；大响应或 DoT/DoH 走 TCP。

Socket

Socket · 程序员的世界

  • TCP/IP 在编程层面的API 抽象——「端点」
  • Berkeley Sockets：socket()、bind()、listen()、accept()、connect()、send()、recv()
  • 一个 Socket = IP : Port 的一对——标识一个网络端点
  • 服务器：bind → listen → accept，被动等连接
  • 客户端：connect，主动发起连接
  • 几乎所有网络程序（C / Python / Java）都基于 socket

Handshake Detail

为什么是三次，不是两次？

两次的问题

旧请求 S/D 问题

如果只有两次，失效的旧 SYN 可能突然到达服务器，让它误以为有新连接，浪费资源。

三次的好处

双方都验证

第三次 ACK 让客户端确认自己发的包被服务器真正收到，「信道是双向可用的」。

一句话：三次握手 = 双方各确认一次收发能力。

Internet Layers

一个完整的 HTTP 旅程（按层）

  1. 应用层　浏览器组装 HTTP GET 请求
  2. 传输层　TCP 三次握手建立连接
  3. 传输层　数据被切成段（segment），加上 TCP 头
  4. 网际层　段被封装为 IP 包，加上 IP 头（src/dst IP）
  5. 网际层　路由器查表，逐跳转发到目的 IP
  6. 接口层　包被封装成帧，加上 MAC 头（src/dst MAC）
  7. 物理层　帧变成电信号 / 光脉冲 / 无线电波在介质上传输
  8. 反向　到达后层层解封装，最终 HTTP 响应回到浏览器
