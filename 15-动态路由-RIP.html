任务情境 · 静态路由的极限

Scenario

静态路由的 3 大局限

规模

配置爆炸

变化

拓扑变更

PART 02

动态路由原理

路由器如何「自动」学到全网路由?

Two Types

动态路由的两大算法

DV

距离向量

Distance-Vector:

每台路由器告诉邻居「我能到某网段,距离 X」;

→ RIP / IGRP(BGP 属路径矢量)

LS

链路状态

Link-State:

每台路由器泛洪自己的链路信息,各路由器计算最短路径;

→ OSPF / IS-IS

Bellman-Ford

RIP 算法 · Bellman-Ford(计算)

计算 · RIP 跳数与最大 15 跳
01
初始跳数 路由加入 RIP 表时,跳数 = 0(本地) → 0 跳 = 直连网络 本地接口
02
首次通告 R1 → R2 通告: 到 192.168.10.0 距离 1 R2 学到: 1 跳 邻居 +1
03
二次通告 R2 → R3 通告: 到 192.168.10.0 距离 2 R3 学到: 2 跳 再 +1

Bellman-Ford

RIP 算法 · Bellman-Ford(要点)

计算 · 逐跳累加与 15 跳上限
01
逐跳累加 每经过一台路由器,跳数 + 1 距离矢量更新
02
上限 15 跳数 15 时路由仍可达,16 = 不可达 RFC 限制
03
实际意义 直径 ≤ 15 跳 = RIP 可用范围 → 大型网络必须用 OSPF 尺度限制
  • 每台路由器维护一张 路由表(目的 + 距离 + 下一跳)
  • 每 30 秒向邻居发送整张路由表（RIPv1 广播 / RIPv2 组播 224.0.0.9）
  • 收到邻居的路由后:
    • 新网段 → 加入路由表(距离 +1)
    • 已知网段但距离更短 → 更新
    • 已知网段但距离更长 → 忽略
  • 这就是Bellman-Ford 算法
  • RIP 限制:最大 15 跳(16 = 不可达)

Timers

RIP 的 4 个计时器

Update

更新计时器

默认 30 秒——每 30 秒广播一次完整路由表。

Invalid

失效计时器

180 秒——某路由 180 秒无更新 → 标记 invalid。

Hold-down

抑制计时器

180 秒——失效期间不接受该路由更新,防路由环路。

Flush

刷新计时器

240 秒——彻底从路由表删除该路由。

Versions

RIPv1 vs RIPv2

维度RIPv1RIPv2
类别支持有类(classful)无类(classless)
子网掩码不支持 VLSM支持 VLSM / CIDR
认证无明文 / MD5
更新方式广播 (255.255.255.255)组播 (224.0.0.9)
路由标签不支持支持(便于策略)
现状已淘汰主流

Loop

RIP 路由环路 · 经典坑

场景

链状拓扑 R1 — R2 — R3,网段 X 是 R1 的直连网络。R1–R2 之间的链路 down。

问题

断链前 R3 已从 R2 学到「经 R2 到 X,距离 2」。R2 失去到 X 的路由后向 R3 询问 → R3 回答「距离 2」→ R2 学到「经 R3 到 X,距离 3」→ 又通告给 R3「距离 4」→ R3 学到 5……两个路由器互相把对方当出口,直到 16(不可达)才停下——计数到无穷。

防御 · Hold-Down

路由失效后,180 秒内不接受更差的路由——给网络收敛时间。

防御 · 水平分割

从某接口学到的路由,不再从这个接口通告出去。

防御 · 毒性逆转

将不可达路由以 16 跳 通告——邻居立即丢弃。

RIP Config

RIP 配置 · 3 路由器

R1>
R1# configure terminal R1(config)# router rip R1(config-router)# version 2 ! 启用 RIPv2 R1(config-router)# no auto-summary ! 关闭自动汇总 R1(config-router)# network 192.168.10.0 ! 宣告 LAN R1(config-router)# network 10.0.0.0 ! 宣告 WAN R1(config-router)# end

Verify

验证 · show ip route

R1# show ip route
Codes: C - connected, S - static, R - RIP, ... C 192.168.10.0/24 is directly connected, FastEthernet0/0 C 10.0.0.0/8 is directly connected, Serial0/0/0 R 192.168.20.0/24 [120/1] via 10.0.0.2, Serial0/0/0 R 192.168.30.0/24 [120/2] via 10.0.0.2, Serial0/0/0 R 20.0.0.0/8 [120/1] via 10.0.0.2, Serial0/0/0

R 开头的 = RIP 学到的路由;120 = 管理距离;后面数字 = 跳数。

Converge

收敛测试 · 断一根链路

  1. 正常时:PC1 ping PC5 通(经 R1 → R2 → R3)
  2. 断开 R2 ↔ R3 之间的串行线
  3. 等待 30-180 秒
  4. 观察路由表变化:RIP 路由 180 秒无更新 → invalid(possibly down),240 秒后才从路由表删除
  5. PC1 ping PC5 失败——RIP 没有备份路径
  6. 结论:链式拓扑没有备份路径(RIP 本身支持等跳数等价负载分担)

Misconceptions

常见误解 · 别踩坑

  • 「RIP 是最古老的协议 → 速度慢」——对。30 秒更新周期,收敛慢;适合小网络。
  • 「动态路由无需人工」——错。仍要宣告网段、过滤路由等。
  • 「RIP 兼容所有厂商」——对。RIP 是开放标准,但 Cisco 有 EIGRP 等私有协议。
  • 「RIPv3 更快」——错。RIPng(RIP for IPv6)使用 UDP 端口 521(不是 IP 协议号),但跳数限制 15 没变。

Case 01

案例 · RIP 学不到路由

故障现象

配置 RIP 后,R1 路由表没有 R 开头的路由——只有直连 C。

诊断

步骤 1:查 show ip protocols → 确认 RIP 启动 & 宣告了哪些网段

步骤 2:接口 UP 了吗?(show ip interface brief)

步骤 3:网络宣告错了?(例如漏掉 192.168.10.0 → 邻居不可达)

解决

补齐 network 宣告,等 30 秒重看路由表。

结论

✅ RIP 不会自动宣告所有直连网段——必须逐个宣告。

Case 02

案例 · version 不一致

故障现象

R1 配 RIPv2,R2 配 RIPv1(默认)——R1 能收到 v1 更新但掩码按有类处理,R2 收不到 v2 的组播更新(单向不通,版本必须统一)。

诊断

RIPv2 默认可接收 RIPv1 更新(向下兼容接收);是 RIPv1 路由器无法解析 RIPv2 的组播更新——混用的真正问题是掩码与自动汇总不一致。

解决

所有路由器统一使用 version 2。

结论

⚠️ 同一 RIP 域内必须版本一致。
